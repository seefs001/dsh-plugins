# ACP native conversation integration

## Goal and scope

The user explicitly selected BOTH modes: (1) use an ACP agent directly inside the current DSH conversation, and (2) let the DSH lead delegate to a native, continuable ACP child. The normal composer, message history, stop button, queues and subagent tree remain the entry points. The old standalone workbench becomes provider administration / diagnostic fallback, not a second chat product.

Do not build another workspace, terminal or schedule product. Preserve existing DSH features. Do not replace the application root, monkey-patch Agents, hijack the global Agent factory, write custom Session event types, or disguise external tool execution as a request for DSH to execute those tools again.

## Project workbench

For the public Paseo implementation used as a baseline, the workflow-by-workflow map, acknowledged gaps and launch state model, see [Paseo parity](./PASEO-PARITY.md). The workspace screen composes DSH services; it does not own a second project registry or chat.

The project finder groups only `workspaces.list` members. The local catalog supplies the DSH title, archive set, pins and session address; ACP bindings supply engine labels and execution directories when known. Multi-word matching spans fields, not transcripts. Always pass the result’s owning workspace and DSH session to checkout inspection and archive, even when another project is selected above. An ordinary fork opens by ID; only a delegated child takes a parent/child target. The native `contextMenu.button` factory owns Session rename/pin and checks access on the captured Session. Workspace rename uses `useWorkspaceAccess(id, 'workspace/rename')` and `workspaces.rename` against the workspace ID; it does not rename a directory, CLI session or historical ACP record.

File discovery is distinct from the conversation finder. The native `workspaceFiles.search` Client lookup starts at the immutable Session header cwd. `project-files.js` resolves an active registry member’s **effective** cwd through `sessionQuery.inspectSession` and `workingDirectory.get` without creating an Agent. Only the Host supplies this root to native search; it checks membership and cwd again before returning and on selection. The Client cancels superseded searches, keeps returned-limit and incomplete-scan flags distinct, and only on selection reads the file via the existing version-checked text preview. Jumping to the native resource uses the selected session and absolute path. No custom scanner, transcript index or editable file tab.

Folder browsing is a separate mode of the same project file picker. The owner-only `project-file-directory` operation supplies the effective checkout to `workspaceFiles.list`, not the immutable session header. The initial empty path lists just the root. Every descent or refresh carries the listing’s directory identity and rechecks membership and cwd before publishing. Only direct, non-dot children are exposed; Git-ignored but visible entries and empty folders can therefore be found. Directory aliases that resolve to a different canonical path are not traversed. Keep the backend truncation flag separate from the client’s show-more button. An obsolete directory request cannot replace a newer breadcrumb selection. Browsing reads no file bodies; search and browsing share the same version-checked file preview and native sidebar handoff.

## Contract findings

- The installed `agents.setFactory()` is exclusive. Replacing the default factory would affect unrelated sessions and cannot replace already live Agents safely.
- `agent/pre-step` can admit/reject messages but cannot claim an externally completed turn: rejection ends the turn as `blocked`. It is not an alternate execution driver.
- The public `llm.registerAdapter()` plus explicit `acp-*` routes can carry a real external-agent turn through the native driver. This is a compatibility bridge, NOT a claim that ACP is a stateless LLM completion API.
- `SubagentProvider.prepareContinuable()` creates a real local DSH child using the normal driver. The official tool MUST explicitly configure `agentOptions: { provider: "acp-…", model: "default" }`: provider `agentRouteDefaults` alone does not select a route when no overrides are supplied. This retains native naming, tree discovery, follow-ups, cancellation and durable messages without a one-shot external SubagentRun facade.
- `Agent.runMaintenance()` claims an idle phase for explicit connection and CLI configuration, including before the first prompt. Composer input queues behind it; native cancel aborts it. Plugin unload cancels and awaits owned maintenance as well as active streams.
- A cold ordinary Session can be explicitly activated through the public `sessionController.resolveAgent()` owner. Read-only snapshots never activate it; the plugin does not take ownership of the global Agent factory or call a model-selection API that persists deployment defaults.
- `uiConversation.events.register()` and a new `conversation.chat.node` key can add ACP execution traces without replacing the shipped assistant renderer. `conversation.composer.dock` supplies pending interactions and child progress, not a second model selector; the shipped subagent tree retains its normal controls.
- Standard assistant text/reasoning/image blocks, cancellation and final messages are committed by DSH. Raw ACP tool/plan/permission events remain plugin-owned, referenced by the bridge's provider replay metadata. They never become DSH executable tool calls.

These contracts were checked against live Inspect and installed owning-package source, including the non-catalogued UI Conversation registration Interface.

## Modules and Interface

- `transport.js`: NDJSON RPC over an owned subprocess. Handles framing, pending requests, errors, cancellation and orderly process exit.
- `store.js`: providers, external session mappings and chunked raw ACP history. Ordered persistence, immutable stored snapshots, explicit storage failures.
- `manager.js`: one external-session operation Interface shared by administration, native bridge and scoped tools. Retains human-only interactions and config changes. Emits an observed event feed; owns live process identity and shutdown.
- `native.js`: maps one DSH Session + ACP provider to one external conversation; registers explicit ACP routes and continuable subagent providers. Translates native input and ACP output, preserves replay references and keeps ambiguous delivery from auto-retrying.
- `index.js`: owned Cordis registrations, owner-authorized HTTP/SSE and model-facing tools. Human authority checks remain at both transport and manager Interface.
- `client.js`: contributes native composer controls, live interaction/trace views and durable Chat nodes. Reuses the original composer and assistant rendering. Retains a small provider administration page.

## Native bridge state model

Subject: one native DSH request and its external conversation binding. Observable seams: the adapter's stream, manager events, native Session messages, and user operations.

| State | Event | Next | Effect / invalid handling |
| --- | --- | --- | --- |
| idle DSH Session | explicit connect / configure | connection maintenance | Claim the native maintenance phase, initialize/load or configure without a model prompt, release it on completion |
| connection maintenance | native stop / unload | disconnected | Abort and await the owned connection; do not submit a prompt |
| no binding | native ACP request | preparing | Persist mapping to exact DSH Session and provider; never share another DSH Session's remote ID |
| no binding | list CLI history | unchanged | List only the selected provider in the native cwd. No prompt or binding. Already-bound entries navigate to their DSH Session. |
| no binding | adopt listed session | connection maintenance | Reserve provider + remote ID, persist its binding, then connect without prompting. Reject a changed route/cwd, an existing native context, or another owner. If the CLI refuses, retain the failed binding rather than substituting a blank context. |
| disconnected binding | native ACP request | preparing | Resume the same ID without replay when advertised and local history exists. Use load for the first import or a load-only CLI; only an explicit method-not-found reply permits a fallback from resume to load. Never create a different conversation on error. |
| preparing | input translated and recorded | running | Persist submitted native message boundary before external side effects; return output through native stream |
| running | tool / plan update | running | Preserve raw trace; render alongside native answer; NEVER yield a native tool-call chunk |
| running | permission / question / plan request | waiting | Persist pending human request and present it in the current conversation |
| waiting | valid human answer | running / waiting | Persist answer before resolving exactly one pending ACP request |
| running / waiting | native stop signal | canceling | Cancel the external turn, expire interactions, await prompt or process cleanup; preserve delivered native output |
| running | external completion | completed | Flush trace, persist native message boundary and replay reference, finish the native stream |
| running / preparing | transport failure | failed | Report failure without automatic retry of an external side effect |
| running | agent JSON-RPC error reply to `session/prompt` | failed run, idle binding | Record `turn-error`, expire this turn's interactions, keep the process and remote session for the next native input; no retry |
| in-flight persisted binding | Host restart | interrupted | No startup process or task; reconnect on explicit native input, never automatically resend ambiguous input |
| completed / failed / interrupted | later native message | preparing | Forward only new native input; include a clearly delimited context handoff when needed |
| any | forked DSH Session | independent binding | New remote conversation with fork context, not reuse of the parent's remote session |

Invariants:

1. At most one prompt per external connection, and the default DSH driver still owns each native turn.
2. The bridge refuses anonymous utility/model-discovery calls. A real live DSH Session and an ACP conversation route are required.
3. Provider routing explicitly says ACP. It does not claim DSH tools, guards, MCP, token accounting or sandbox govern the external CLI.
4. No automatic external-task retry. A lost response can mean an operation already happened; record uncertainty and require new user intent.
5. All user inputs visible to the native model history remain native durable messages; no fabricated Session event types.
6. Raw external tools are informational. They are not dispatched again through DSH's tools pipeline.
7. Native provider replay metadata stores only references and delivery checkpoints, not credentials. Every finished run has a `to` sequence, including runs interrupted by a Host restart, so a trace never spills into later turns. A persisted native assistant message ID also indexes the external run: canceled streams may not deliver finish/replayState, and a fork must still locate the original canceled trace without guessing from its new Session ID.
8. No permission granted by tools or by an expired/duplicate interaction. Mode/config changes remain explicit human actions.
9. Missing usage is unknown. Context-window usage is not relabeled as input token usage.
10. Unload and cancellation await owned subprocess cleanup; stale generation callbacks cannot mutate a new connection.

## Composer command ownership

Paseo's provider-command pick edits the input. Here the writable native composer supplies one leading slash source to DSH inputTriggers. Offer only the selected idle record; load descriptions and argument hints on demand. A pick claims a namespaced chip, never sends input. DSH owns the arguments, selection and submit. An explicitly submitted chip calls the same user-only native-command operation as the existing options form, carrying the original record and advertisement revision. Restored chips know only their spelling: they cannot reauthorize a new connection. Plain DSH commands and inline text are outside this source.

Command advertisements are live process state, not executable journal history. During startup keep the latest list per reporting remote until new/load resolves; ignore other remotes and child tool updates. Disconnect removes the usable list. A superseded selection fails rather than dispatching a command to another engine.

## Activity inbox and conversation navigation

The sidebar used to start in the provider editor; a waiting turn, an interrupted run and an intentionally disconnected record looked alike in a chronological list. The comparison point is Paseo's `packages/app/src/components/agent-list.tsx` and `packages/app/src/utils/agent-attention.ts`: a user can locate a conversation that needs them, and focusing it does not answer a permission request. We adopt those interaction properties, not Paseo's daemon or a second inbox for messages.

Subject: one external binding in the activity index. The index is calculated at read time from the manager's live interaction map, connection state and last run; it owns no lifecycle or persistence. In descending priority:

| Fact | Inbox group | On opening |
| --- | --- | --- |
| Archived or retired | History | Inspect only, or restore an archive explicitly. Never reconnect a retired binding. |
| One or more unanswered requests on a live, non-closing turn | Needs you | Show actual decision cards first. Opening does not answer them. |
| Connecting, preparing, executing or stopping | In progress | Show status; stop must target the observed operation, not a later native turn. |
| Failed connection, failed/interrupted latest run or recorded restart | Review | Retain history. Reconnect and sending a new task are separate actions. |
| Everything else, including intentional disconnect and completed runs | Recent | Inspect the record or return to its conversation. |

Answer, expiry, stop and restart remove actionable requests from the live map. No acknowledgement flag or unread count is stored. Detail and the composer share the same manager operations. A normal Session opens by ID; a new child binding records its direct-parent address. An old cold child without this address offers its root conversation rather than guessing the parent. The full-access preset can select a one-time grant only; a durable grant always requires an explicit choice.

## External manager lifecycle

The existing manager retains disconnected → starting → idle → running ↔ waiting → idle. Cancel enters canceling and disconnects after its grace period if the provider does not finish. Transport and process failures close the owned connection. An error *reply* from a live connection is an agent decision, not a broken transport: a rejected prompt records `turn-error` and returns to idle, and a rejected mode/model/config change records `configuration-error` and returns to idle with the previous setting. `AcpConnection.stop()` only awaits quiescence; failures already reported through `fail()` are not raised again as cleanup failures. Import preserves a discovered remote ID; archive is metadata only. Host restart marks formerly live records disconnected.

Native-bound records cannot receive independent workbench prompts: the DSH composer owns their inputs. The administration page may inspect them and answer existing human interactions, but must not create a competing turn stream. Model tools get read-only access (`get`, `events`) to native-bound records; archiving or disconnecting one from a tool would otherwise break that conversation's ACP route.

### Reopening retained terminals

The project row watches DSH `terminal/watch` only while expanded and authorized for that session. Each frame replaces the list; unmount, loss of access or a stream failure removes old rows. A shared checkout is not a shared terminal owner. An explicit open targets the owning root/fork or delegated child. Once that conversation has a sidebar seat, focus the existing tab or bind the new tab to the reported terminal ID. Never open an unaddressed terminal tab as a fallback. The project list does not attach to the PTY or change control. Script output and ordinary ACP command reports remain separate from this inventory.

### Reported web activity

A fetch launch may carry the *extraction prompt* as ACP display content. Both event folds retain the frame that supplied this content; a later status-only update does not make it a response. Claude ACP’s `WebSearchReporter` projects its interleaved commentary and hits as lines; the card preserves their order using DSH `WebBlock` for sources and plain text for commentary. The SDK’s richer HTTP/snippet fields need not reach ACP. Codex’s `WebSearchEnd` carries the planned action, not search hits: inspect `rawInput.action` for queries, target or pattern, never the assistant reply. Do not treat a fetched body, failure or permission preview as a source list. No webpage rendering, network prefetch, or automatic link following.

### MCP calls and permission subjects

The same read-only card serves the native trace and standalone history. Detect Claude's reported `mcp__<server>__<tool>` name, or the Codex ACP invocation's `server/tool/arguments` fields with its exact `Tool: server/tool` title. A title by itself is not a tool identity. Never interpret a remote tool's argument named `command` or `path` as a shell command or local file. The Codex projection keeps the original MCP result (including `structuredContent`) separate from ACP display blocks; views of a mixed result preserve block order and never render both projections at once. Small homogeneous arrays of flat records use a paged table; other arrays and objects expand by key. Unknown block types remain inspectable.

Claude repeats its actual tool name on a permission request. Codex can instead send a form with `codex_approval_kind=mcp_tool_call` and a request ID corresponding to the subject's call ID; `tool_title` is a display label, not an executable tool ID. Present raw and display arguments separately. Opening this card never invokes an MCP service or decides a permission request. See the installed Claude adapter's `tool-calls/renderer.js` and the [Codex ACP adapter](https://github.com/zed-industries/codex-acp/blob/296069e841634cd4bb9bc4515602d836e49231ec/src/thread.rs) (`start_mcp_tool_call`, `end_mcp_tool_call`, `build_supported_mcp_elicitation_permission_request`).

### Display-only command output

ACP v1 connections negotiate `_meta.terminal_output` and `_meta.terminal_output_delta` while leaving `clientCapabilities.terminal` false. No RPC for creating or controlling a terminal is added. Bind the transcript to the explicit `terminal_info` plus matching content reference and tool ID in the same run. The installed Claude ACP 0.107.4-preview.8 (`v1/background-work.js`, `tool-calls/background.js`) sends explicit deltas and uses `terminal_output` to replace the foreground transcript. In [`codex-acp` at 296069e](https://github.com/zed-industries/codex-acp/blob/296069e841634cd4bb9bc4515602d836e49231ec/src/thread.rs), `exec_command_output_delta` instead uses `terminal_output` for ordered chunks. Determine the convention from the announcement, not the provider's editable name; an unknown format shows its latest ambiguous report and any subsequent explicit deltas, with a notice.

Keep a 32 Ki-character tail per display terminal; snapshots replace both text and its clipping flag. Original wire packets remain in the event store. The card never interleaves a separately reported aggregate with the stream, assumes a missing exit code is zero, or turns a terminal reference into an interactive DSH terminal. Existing ACP text, media, approvals, and the native terminal panel keep their own paths.

### Human form responses

The execution connection advertises ACP v1 `elicitation.form: {}`, not URL elicitation. `elicitation/create` must identify the bound CLI session during an active prompt. The Host parses the reported form once: single string enums, string-enum lists and free text, including required fields and size constraints. Unsupported schema variants return JSON-RPC `-32602` without creating a partial form. Defaults are not submitted silently. The client renders option descriptions and Claude’s optional preview as inert text. It uses the same human-only response route, activity inbox and chat controls as other requests. Permission presets never answer questions.

`accept` carries only validated field values, `decline` carries no response, and `cancel` dismisses. A `$/cancel_request` for an unanswered form matches the exact incoming JSON-RPC ID on that connection; session shutdown expires remaining forms. The action receipt survives disconnects. It does not persist the form response content or re-create active controls, although later CLI output can echo an answer. This is not an authentication prompt, general-purpose schema editor, or support for request-scoped or foreign-session elicitation.

### Project conversation housekeeping

Bulk archive/restore is a Client workflow over the existing `uiWorkspace.archiveSession(id, {stopActivity:false})` and `unarchiveSession(id)` commands, not a privileged Host batch endpoint. Use the selected workspace and filtered member rows, with per-session DSH access hooks. Never preselect items. Switching project, query or archive view drops the checklist. Confirm explicit titles and IDs, then process sequentially and return a result per item. Unmount aborts any preflight and abandons **remaining** items; it does not roll back a native command already issued.

Re-read current membership and archive state before each command. Bulk archive requires checkout inspection and omits any recorded tree (including shared/inherited records); the single-session action retains the path and cleanup warning. The DSH registry remains authoritative for concurrent activity and pin removal. The ACP execution provider contributes its active request, startup or pending interaction to the native `workspace/session-activity` check. No stop-on-archive escalation, pin restoration, worktree recreation, new prompt or external record archive is part of this operation.

### Provider notices without impersonating the assistant

Execution connections advertise `clientCapabilities.session.notices: {}`; discovery, model probes and fork-only connections do not. In the installed Claude ACP v1 adapter, `noticeOrTranscriptUpdate` switches from a synthetic chat line to a typed `notice` when this capability is present. Only that explicit frame gets a notice row. Treat the title and optional description as inert text. Preserve unknown severity strings without escalating them to errors. Each receive is distinct even if the text is identical. A notice cannot start, settle or authorize a tool call, change the DSH model route, or become a final reply.

Native runs show receipts matching their prompt and exact remote session. During setup and between prompts, the selected composer shows at most eight lightweight heads from its current connection. A notice delivered during `session/load` reports what the CLI is telling the connected client now; it is not an imported historical chat message. Resolve an expanded off-turn description from its pinned local event, not another request to the provider. Disconnect/reload discards the live heads. The local journal still shows what this Host received; it does not promise delivery, an unread count, acknowledgements, cross-device notifications or historical replay by the provider.

### Explicit CLI context compaction

Execution connections advertise `clientCapabilities.session.compaction: {}` (ACP v1 draft). `compaction_update` creates or patches a stable session-scoped marker; `compaction_summary_chunk` appends to it and can open it without a start frame. Status does not imply a summary. Omitted summary/error/metadata keep their prior values; explicit null and empty summary arrays clear them. Only a supported, explicitly reported extension supplies trigger, before/after counts or duration. Do not advertise an AIR client identity to obtain them. Older Claude `think` tool reports with the actual `claudeCode.toolName: compact` marker retain their tool identity. An English title, usage drop or DSH checkpoint alone is not a compaction.

In the record timeline a live marker retains its first position across prompts; a load replay has a separate scope. In native chat a marker belongs to the run that first received it. Persist this owner and the sequence ranges of late patches, not duplicate content. Read those ranges only for the owning trace and mark late updates as such. Idle-only markers remain in the external record. A finished turn with only `in_progress` is not a completed compression. The reported summary stays in the trace, not the assistant message. Render text/resources as inert text; media buttons resolve a specific local journal frame only on request. Unsupported attachments remain labeled, raw frames remain in diagnostics.

### Context occupancy and accounting

The native composer already has a DSH usage cell. Leave it intact. The ACP dock adds a read-only disclosure only if the selected provider has a non-retired, non-archived binding in this DSH conversation and a valid live `usage_update` for its remote session. A zero `used` is meaningful; a missing or zero window size is not. Remember the arrival time and the last **whole** valid window report. Neither historical `session/load` frames nor parent-stamped CLI task reports replace it. Do not carry forward an old cost, unit or model when the next sample omits it. The native snapshot returns only this small projection, not arbitrary adapter metadata.

A run trace coalesces root window samples within its turn. The record timeline marks replay and does not group observations with no known turn. Separately, ACP `session/prompt.usage` is cumulative for the external session (`Usage` in the v1 draft; the Claude adapter builds `sessionUsage` from `session.accumulatedUsage`). Keep this **as reported at the end of the prompt**, with optional cache/reasoning counters. DSH stores model-stream `usage` on an individual `assistant/message`, so do not forward the cumulative object there or subtract an unknown baseline. This is not a quota or billing integration. Historical DSH messages are not rewritten.

### Recorded plans

An execution connection advertises the ACP v1 draft receive-only capability `plan: {}`. `plan_update` replaces one ID with a full checklist or Markdown document. `plan_removed` replaces just its current content with a withdrawal receipt; it is not a completion or a decision. Native traces fold within one run. The record timeline separates connections, turns and replay from live data. Plan IDs are opaque and scoped to the external session, not tool call IDs. Attribute a plan to a CLI task only by an explicit parent stamp, never by parsing the plan ID. An unstamped removal can clear the same ID. Legacy ACP lists and Cursor merge updates keep their own keys.

A plan document is reported text, not necessarily a file, and does not prove approval. Its disclosure renders inert Markdown source in the native code viewer. Only the separately reported absolute path can open the current file, on click. This does not install a global plan board, reconstruct earlier turns, or answer an outstanding request.

### Recorded patch evidence

A tool row remembers which content-bearing frame supplied its patch: launch, update, completion, or failure. An unrelated status update does not relabel it. Permission requests have their own provenance. Both the native and standalone folds keep only the stage and the name of the matching raw field; they drop the field pointer if a later frame replaces it without new content. Explicitly cleared diff content is not reconstructed from a stale raw result.

The file selector indexes ACP `diff` fragments by their exact reported path, preserving original order in the combined view. Empty old/new sides may be snippets inside an existing file. Operation names require explicit same-call evidence: see [`zed-industries/codex-acp`’s `start_patch_apply` / `end_patch_apply`](https://github.com/zed-industries/codex-acp/blob/296069e841634cd4bb9bc4515602d836e49231ec/src/thread.rs) and the tagged `FileChange` type in its pinned `openai/codex` `rust-v0.137.0`. A move can name its destination without supplying a text hunk. Unstructured text, errors, resources and raw fields remain available. File selection uses only recorded data; opening a current file is a separate user action.

### Tool call display levels

The canonical trace still has one row per external call ID per run. A text-free section marker preserves answer, thought and plan boundaries that would otherwise disappear when DSH renders messages itself. Overview projects adjacent completed reads, searches and web lookups onto the first row's stable sequence. It counts calls, not successful matches or lines changed. Execution, writes, unknown calls, rich results, nonfinal status, failure, explicit permissions and replay remain separate. Detailed mode shows the original rows. Switching modes affects only local presentation; expanded details follow the same call when the live result joins a group. A matched request, an active pending approval, an automatic allow, a human decision and an expired request are different facts. The trace never answers a request or runs a tool.

### CLI-reported tasks are not DSH agents

A Claude ACP `_meta.claudeCode.parentToolUseId` is a direct edge to the Agent/Task tool call in the **same turn**, not a DSH session or permission grant. A CLI task is identified by a typed launcher or an explicit incoming edge. Keep the edge when a later tool update omits metadata. If two parent IDs disagree on a call, leave it unassigned. Missing launchers remain visible with the reported ID. Native run projections exclude replay; standalone pages do not infer relationships across turns or replay. The index and drill-down are presentation only. They never create, message or stop a provider child. Call status describes the launcher, not a background worker lifecycle.

Only untagged output is streamed as the native parent's answer/reasoning/attachments. The trace folds tagged visible text in consecutive segments (16 Ki characters each) and scopes plans by parent ID; it does not copy child thinking. Binary task progress uses an exact event pointer; only an explicit preview reads that event and validates the parent, sequence and message kind. The read-only raw stream remains unchanged. Recorded DSH messages from before this separation are not rewritten.

### Locating a file from project review

A Forge file path is relative to the Git top level, not necessarily the effective cwd, the project root or the immutable session header. Observe `forgePanel.follow` for the session whose diff is on screen and discard the comparison when its checkout changes. For working-copy scopes (including whole-branch comparison with no commit range), read a bounded `workspaceFiles` page at the **absolute** path. Verify the resolved path, version and available new-side hunk lines before offering native sidebar navigation. A cold sidebar opens only after its target conversation mounts; the line is a navigation parameter, not part of the resource identity. For the index use `forgePanel.localText` and show its verified new-side text in the review, never the disk file at the same name. Deletions and missing-newline markers do not acquire new-side line numbers. These are current reads, not a historical-run snapshot or a guarantee against later edits.

For historical Git review, `forgePanel.localCommits` lists a bounded window between the selected fork point and HEAD. Load the history list only for commit review. A full old-side HEAD read can also request `headSha` against the current branch (or Forge's automatic base for a detached head), without listing history in the UI. Unlike whole-branch review, `localDiff` receives a pair of full Git object IDs, never a row index, title or shortened SHA. The range begins at the first commit’s first parent; only consecutive first-parent chains in the returned topological order are selectable. On refresh, check the listed HEAD against the observed checkout and revalidate both endpoints before rendering a patch. Losing an endpoint must not silently widen the comparison to the working tree. New-side file text comes from `localText` at `commits.to`, not the current disk, and does not open a disk sidebar. No write-capable Git service is required.

The left gutter uses `oldStart` and the rename source path. It first shows only the context and deleted lines already returned in the Forge hunks, with original line numbers and explicit gaps. Reading a full old file is a separate action. For unstaged changes, use `localText` against the Git index; for staged or uncommitted changes, resolve the observed HEAD to a full object name. Check all captured old lines and, for these live comparisons, recheck the file digest before displaying the result. Commit ranges use the first selected commit's first parent, not the parent of the end commit. A whole-branch comparison only offers a full read when Forge supplies the matching created worktree's exact base commit; a ref label is not the merge-base object. Missing objects, binary files or read failures never fall back to the current file. Old-side content stays inside review.

A permission request and the tool’s launch are two distinct records, even when they name the same call. The bridge keeps only the unique launch sequence and CLI task parent per call in the active prompt. A new permission may reference that earlier sequence; neither the arguments nor subsequent tool updates are merged into its terms. Duplicate starts, conflicting task origins and earlier prompts do not qualify. The dock and history read launch evidence only on disclosure, validating record position, turn, call ID and parent. The timeline loads the original permission by its own position and request ID; advertised choices are labels there. It does not render the live response control. Old requests without a launch pointer remain readable without a guessed association.

Recorded ACP tool locations use a different base: the persisted CLI binding’s cwd, or an explicit per-call working directory, even if the DSH session later enters another checkout. `FilePreview` also serves these explicit user clicks. It uses the session-scoped native file reader, keeps the resolved path and version for subsequent pages and sidebar navigation, and labels disk contents as current. A numbered read window needs one file. Search matches need a path and positive line; an explicitly single-file Grep content result can supply the missing path. A count or an opaque shell command supplies no line. Opening a result or trace alone performs no file read.

## Context and capability boundaries

On a first ACP use, native conversation content can be handed off as clearly delimited historical context. Only user message IDs committed after the current `step/start` are new tasks. At dispatch, the bridge reads the open turn/step and logged route from the native Session rather than an in-memory `agent/pre-step` observation; late activation or reload must not misclassify a valid first request as a utility call. Later requests do not resend the prior ACP transcript or user tasks completed while another engine was selected. Such intervening work becomes delimited historical context. Closing connections are awaited before reopening the same binding. Native system/developer messages and tool schemas are not reinterpreted as ACP system authority; the CLI owns its own system prompt and tool set. Context limits and unsupported current attachments must be reported, not silently dropped. Current images use the attachment service; normal DSH file lowering provides a read-only host path, with resource links for unlowered file blocks. Historical attachments use textual descriptions rather than bulk retransmission. Resource text is rendered natively; unsupported binary output receives an explicit pointer to raw events.

A model route can be selected from the native picker. Selected IDs remain user settings; descriptions, supported bridge input modalities and explicitly reported capacities are discovery facts joined by exact ID. Discovery emits `llm/models-updated` for changed metadata without enabling candidates. Unknown capacities and prices stay unknown, and a reported output limit is not an adapter-configured request cap. Model badges surface ACP/image/context information through the native label renderer. The native effort control receives only advertised reasoning levels: a model's standard `thought_level` select option, or `reasoning_effort` values from an advertised variant family. Other variant parameters remain fixed; IDs are looked up, never constructed. The chosen effort is applied before prompting, and refusal sends no prompt. `CLI default` preserves the CLI's current model and reasoning configuration. Provider configuration, optional model catalog discovery and ACP mode/config controls remain explicit UI operations. Authentication stays with the installed CLI. Cursor private model-catalog discovery is not implemented; the UI uses standard advertised controls. External advertised slash commands are explicit human operations that enter the ordinary native inbox, bypassing only the DSH slash parser. DSH composer slash commands are unchanged.

ACP client filesystem/terminal capabilities remain false unless fully implemented with an explicit authorization model. The external CLI can already manage its own tools. No credential files, account quota endpoints, relay setup or browser automation are implicit parts of this bridge.

## Project service readiness

`script-start` can assign an ephemeral IPv4 loopback port to a service whose definition has neither `port` nor `worktree.servicePorts`. It requires a separate confirmation and revalidates the definition revision. Ordinary starts retain their original environment. Allocation and TCP sampling use fixed Node helpers via DSH’s read-only sandbox and subprocess service, in the same execution environment as the terminal. Project text is never run to pick a port. The owner’s `script-health` operation accepts a terminal identity, not an address: it resolves the port from the current retained run and checks the session, checkout, terminal state and agent control before and after sampling. A released ephemeral port is not a reservation against unrelated processes. The UI reports only TCP reachability, not process identity or HTTP application health.

Only one explicitly opened card polls, after a five-second launch grace and at three-second intervals. Two distinct failed samples confirm a negative status. Listing scripts, reconnecting the plugin and following the terminal do not start monitoring or relaunch a process. The port number survives a reload alongside the terminal ID; samples do not. No public URL, service proxy or cross-service environment is implied.

## Interface surfaces

The browser half reuses DSH primitives (`Button`, `StateDot`, `DisclosureRow`, `DiffBlock`, `JsonBlock`, `PathLabel`, `Pill`, `Switch`, `Tag`, `SegmentedTabs`) and the host design tokens. One stylesheet is injected for all instances, and all surfaces share one `/acp-workbench/events` EventSource, because each EventSource holds a connection and browsers cap them per origin.

- **Model picker.** Native ACP routes list only the models explicitly checked and saved in ACP Settings, alongside `CLI default`. Discovery, connection and model-option notifications update candidate metadata without changing the selected list. Saving the model selection emits `llm/models-updated`; existing manually configured models remain selected. A concrete selection is applied before the prompt; refusal sends no prompt. `CLI default` retains the CLI’s current model. Refreshing candidates is an explicit provider-settings action that creates an empty session and sends no prompt.
- **CLI settings in the model menu.** Only an ACP selection adds a settings action. It opens the current binding’s modes, config, commands and usage in a popover above the composer without resizing the composer dock. Before the first connection, the popover shows first-use help and a history picker that calls `session/list` on demand. After adoption, an immutable sequence range references the initial replay. Previous messages page from this range only on demand; they are not new native messages.
- **Branch from CLI history.** The same native picker can copy rather than adopt. On a human action the destination holds its DSH maintenance slot, rechecks the exact source ID on its original `session/list` page in the effective cwd, and calls `session/fork` once. The setup process declines client requests. On success the new remote ID and its source are stored together as an imported, disconnected binding. No `session/new`, prompt or DSH transcript merge. A later connection uses the ordinary load/resume flow. Failure is not retried automatically; check CLI history if the reply was lost. This branches saved CLI history, not the DSH message tree or files.
- **Composer dock.** The selected ACP route can show context-specific recovery for an existing binding. Selecting an ACP model before the first connection does not add a card. Human requests remain actionable even if the selected picker route changes. Active children and problems are visible; quiet children are grouped. A decision is independent of trace expansion. Child navigation uses DSH workspace navigation.
- **Chat trace.** Ordered execution rows stay inline while the run is active and after it completes; there is no run-level disclosure or automatic collapse. The `native-trace` endpoint folds and caches raw chunks on the Host, returning the complete ordered list of tool rows, plans, CLI logs, interaction outcomes and errors, including older runs outside the recent snapshot. Each ACP kind maps to a localized action and an independently expandable result. Chat and Activity share the presenter. ReadBlock, SearchBlock, DiffBlock, TerminalBlock and WebBlock consume only recorded facts; unknown formats fall back to readable output and opt-in diagnostics, without synthesizing a native execution. Chat file navigation uses the owning chat node’s openFile callback. Permission previews reuse the same body without a finished/run indicator. `run.tools` and `run.files` remain quiet summary metadata. Reply text, handshakes and metadata updates are omitted because DSH renders the reply itself; only the optional raw view pages transport events lazily.
- **Shared checkout launch.** A new root keeps the DSH project's header and joins the selected checkout with workingDirectory.set. The browser contributes only a project, a participant ID and a reviewed revision, never a path for execution. The Host resolves the creator's recorded identity and confirms that Git still registers that path and branch under its session policy. A small checkout_links record remembers the launch selection, not ownership or live membership. Pending join → verified join → select route → open conversation; a failed or interrupted join keeps its new session ID but cannot send ACP input to the project root. The native working directory protects an active borrower's directory from creator archive. Borrower archive does not delete the checkout, and we do not add a second last-user cleanup policy. The on-demand group list checks current project membership, archive state and effective cwd. It never opens peers to show them or fetches their transcripts. CLI contexts and tool approvals remain per agent.
- **Checkout lifecycle.** The worktree projection, not a browser path, supplies the creation identity and fork ownership. A cold read uses `sessionQuery.inspectSession` (no agent activation). Archive membership, the current filesystem entry, and the latest Host-lifetime cleanup attempt are independent. Unarchive can join or cancel native cleanup; it never means the checkout is back. Only explicit, same-project, owned, still-selected, missing checkouts may enter native Agent maintenance for reconstruction. DSH serializes the Git operation and decides whether the branch had to be recreated at the pinned commit. The workbench has no remove/force/rebase operation. An implicit working-directory validation on an ACP route refuses a missing checkout or missing linked-checkout marker rather than allowing DSH to recover to header.cwd before the first external call. An explicit directory change remains a DSH operation; an existing CLI binding must still pass its cwd check.
- **Project review.** The default Projects tab indexes terminal runs in the selected workspace's root conversations and their DSH children. The owner can acknowledge a single binding/run pair. A new run starts unreviewed, remains ineligible during execution, then enters the review queue on completion, failure or interruption. Acknowledgement survives reconnects independently of later runs. Legacy runs have unknown review state and are available in history only. The list is passive: it opens no agent and does not clear permissions. Only the final DSH text excerpt is retained, never a reasoning excerpt. The exact folded run trace is historical; the optionally requested Forge comparison reads the conversation's current checkout and is not evidence of authorship.
- **Sidebar.** Activity uses the index above. Search and group controls do not fetch histories; the selected record pages its timeline and raw diagnostics. Providers is a separate tab for explicit configuration, capability checks, catalog selection and imports. All ordinary messages still belong to the native composer.
