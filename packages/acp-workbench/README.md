# dsh-acp-workbench

把 Cursor、Antigravity 等本机 ACP Agent 接入原有 DSH 会话。包名保留兼容，界面入口是原模型选择器中的 ACP 提供方与具体模型、每轮回答旁的 **执行轨迹**，以及侧栏 **ACP 工作台**，不再提供另一套聊天输入框。

支持两种用法：

- **直接执行**：当前 DSH 会话选择 ACP 引擎，继续使用原输入框、附件、消息时间线和停止按钮。
- **DSH 主导委派**：保留普通 DSH 模型，使用 `subagent_cursor`、`subagent_antigravity` 或 `subagent_acp_claude_code` 创建原生、可续聊的子任务。进展与人工交互出现在父会话中。

不依赖 Paseo daemon 或 Hub，不替换全局 Agent factory，不重写 DSH 工作区、Git、终端或定时任务。

## 准备

1. 在终端安装并登录对应 CLI。
2. 通过 DSH 插件管理器安装本 bundle。开发时可安装本目录的 `link:` spec。
3. 打开侧栏 **ACP 工作台** 的 **提供方** 页，核对可执行文件和参数。默认提供 `cursor`、`antigravity` 与 `claude-code`，优先使用 `~/.local/bin/` 下已有程序，否则使用 PATH 名称；前两者参数为 `["acp"]`，Claude Code 使用 `claude-agent-acp`，不传参数。
4. 可填写绝对工作目录，点击 **检查能力**。该操作只进行 ACP initialize，不发送模型任务。

保存配置、打开页面、刷新页面和 Host 启动都不会自动启动外部任务。不要把密钥填入命令参数。

## 按项目开多个 Agent

打开 **ACP 工作台 → 项目**，选择 DSH 已保存的工作区，或用 **添加目录** 从本机选一个。点 **新建 Agent**，选择引擎、模型和工作目录。可把这组选择保存成具名启动配置，在另一个项目复用。创建会打开独立的原生会话，既不发送提示词，也不修改全局默认模型。

**找回或整理会话：** 在「项目会话」输入会话名、项目、已知引擎、目录或 DSH 会话 ID。默认只查当前项目，选 **全部项目** 可跨目录查找，结果按所属项目分组。会话行的 **…** 打开 DSH 原有菜单，可改名或置顶；**只看置顶** 使用与侧栏相同的置顶记录。已归档的会话单独查找，先恢复才能打开。**重命名项目** 只改 DSH 工作区显示名，不移动目录。

启用 DSH 的 worktree 能力后，可选择 **独立工作树**，指定新分支和起始 ref。项目会话仍归原工作区，外部 CLI 在新 checkout 中工作。准备失败会留下可查看的会话，不会偷偷改在原目录运行。归档/恢复使用 DSH 会话身份。进入聊天后在 **CLI 设置** 可以打开已启用的文件、Git 改动或终端面板。

**查找文件：** 知道名字时，在项目会话行点 **查找文件 → 按名称查找**，输入文件名或相对路径片段。搜索使用这个会话的实际工作目录，包括未跟踪文件，跳过隐藏文件和 Git 忽略项。

不知道名字时，切到 **浏览目录**，逐层查看文件夹，点路径上的目录名即可返回。目录模式也列出未隐藏的 Git 忽略项，例如刚生成的构建产物。进入目录只读取条目和大小，点文件才预览或打开原生侧栏。大目录若被 DSH 截断会明确提示；会话换了工作树后，点 **重新打开当前工作目录**，不会把旧路径自动套到新目录上。

**接回已有终端：** 点项目会话行的 **会话终端**，能看到这个会话中的用户终端和 Agent 终端。标题、目录、当前控制方、运行状态和退出码来自 DSH。列表会随终端改名、退出或关闭而更新，不读取屏幕、不发送输入。点 **打开终端** 才切到所属会话的原生侧栏；标签已打开时直接定位，不再新建。共享 checkout 的会话也不混列。

**运行项目脚本：** 在项目会话行点 **项目脚本**。面板读取该会话实际工作目录中的 `paseo.json`，展示每个 `scripts.<name>.command` 和命令全文。点 **运行** 并确认，才在该会话沙箱下的独立 DSH 终端执行。普通任务能看退出码；长驻服务可看输出、打开原终端或停止。DSH 保留每个 checkout 每个脚本最近一次运行的状态和最多 8 KiB 输出。服务命令若读取 `$PASEO_PORT`，可点 **带回环端口启动**。确认后将空闲端口作为 `PASEO_PORT`、`127.0.0.1` 作为 `HOST` 传给命令。点 **监测端口** 才会定期尝试连接；关闭监测不会停止进程。TCP 接通不保证应用响应正常。配置了固定 `port` 或 `worktree.servicePorts` 时只提供普通启动，不猜测端口或执行分配脚本。没有服务代理，也不会执行 worktree setup/teardown。此入口需要 DSH 工作区文件、终端控制器和可用 POSIX shell。

**查看 CLI 自己派出的任务：** 当 Claude ACP 报告父调用 ID 时，任务的直接调用、计划、进展和审批回执带有来源。点 **查看子任务** 只看该任务；多任务可用 **本轮 CLI 子任务** 切换。这个视图只读，不会创建第二个 DSH 会话。原生子代理的续聊与 Stop 不变。

**共享同一份代码：** 在独立工作树会话的 **工作目录 → 在这里新建 Agent** 选引擎。新 Agent 直接使用同一份文件，但会话、外部 CLI 上下文、审批和 Stop 独立。聊天中的 **切换同工作树 Agent** 可直接打开其他参与会话，无须回项目列表。共享成员不获得重建或删除工作树的权限。

**工作树恢复：** 点项目会话行的 **工作目录** 可看生效目录、创建记录和回收结果。先恢复会话，再按需重建缺失的独立工作树。保留的原分支和“原分支已消失，只能从起点新建”会分别提示。原路径被占用时不覆盖，不自动在源项目继续 ACP 执行。归档可能回收未使用且 Git 可见状态干净的目录，不能靠 Git 状态保护被忽略的文件。

**审阅项目成果：** 项目页先列出等你回应的请求，包括项目根会话下的子代理。下方按轮次显示已结束的 ACP 运行；读回复摘录、展开本轮轨迹、打开所属对话都不会代你确认审批。点 **标为已审阅** 仅清除这一轮；已阅及升级前的记录在 **全部结果**。结果卡或会话行的 **工作树改动** 按需读取会话当前 checkout，可对比 HEAD、暂存区或所选分支，不把整个 checkout 的改动算在该轮名下。点补丁右侧行号可查看对应工作树文件，并在该会话的文件侧栏继续阅读；已暂存的行只打开 Git 索引内容，不跳错到工作副本。

**看删除前的内容：** 点补丁左侧行号，无需重新读文件就能查看补丁里的旧行。要读上下文以外的内容，点 **读取完整旧版本**。未暂存比较读索引，已暂存或工作树与 HEAD 的比较读 HEAD，提交范围读起始提交的第一父提交。重命名读旧路径。分支基线只有名称而没有确定的旧提交时，只显示补丁片段。

**看某次提交改了什么：** 在 **工作树改动 → 对比范围** 选 **分支上的提交**，再选提交。需要看一组改动时，用 **比较到** 选结束提交。右侧文件预览以结束提交为准，不含暂存区或磁盘上的后续修改。列表为空可切换基线分支。

**从调用回到文件：** 点结果卡里的文件名，或打开 **本轮轨迹** 查看读取、搜索命中和编辑位置。这里按调用时的目录读当前磁盘文件，不会因为会话后来切换工作树而打开同名文件。原来的调用输出仍留在轨迹里。

**定时唤回或启动 Agent：** 在项目页点 **定时任务**，选已有会话、首次到期创建后复用，或每次到期新建。已有会话沿用当时选择的引擎和工作目录；新会话使用项目目录和 DSH Agent 预设。项目列表支持立即投递、暂停/恢复、删除，以及按投递回执跳到实际对话；点 **管理任务** 可进入已启用的 DSH 原生详情页修改配置。暂停、删除不会撤回已投递的消息；投递成功也不代表 Agent 完成。定时器和历史都由 DSH 核心持久化，关闭工作台不影响任务。

对照 Paseo 的实现入口、替代关系和尚缺功能见 [行为对照表](./PASEO-PARITY.md)。

## 用法一：直接在当前会话执行

1. 打开原有 DSH 会话，在原模型选择器中选择 ACP 提供方下的具体模型。
2. 如果还没有模型目录，到侧栏 **ACP 工作台 → 提供方** 填写工作目录，点击 **刷新模型**，勾选需要显示的候选模型，再点击 **保存模型选择**。刷新只新建空 ACP 会话读取目录，不发送任务，也不自动加入主选择器；后续连接与配置更新只更新候选目录，不改变已选列表。
3. 使用原输入框提问或发送附件。回答、思考文本与返回图片由 DSH 原生渲染。每轮的 **执行轨迹** 默认折叠为一行摘要（状态、工具调用次数和改动文件数），点击即可展开或收起，展开后按发生顺序向下列出工具调用、计划、审批结果和 CLI 日志。默认 **概览** 会把连续完成的读取、搜索和网页查询合成一行，可展开查看每次调用，也可切到 **逐条**，浏览器会记住选择。正在执行、失败、涉及审批的操作、命令和改动仍单列。原始事件不受影响。工具行直接写明动作、目标和状态：读取文件列出路径和行号，点击展开后的路径用 DSH 预览文件；编辑在行上标出 `+/-`，展开可按文件查看 diff 或切回 **全部报告片段**。标签说明补丁来自启动预览还是之后的回报，不用工具的完成状态代替文件核验；命令用只读终端卡显示输出、退出码或信号。CLI 支持分段回报时，运行中就能看；另报的汇总输出若与实时记录不同，可在卡片内切换。卡片不是交互终端；可识别的搜索结果按文件和行号分组，网页来源可点击。等待审批时可先看命令或改动预览。MCP 调用直接显示服务名和工具名，展开后可切换参数与返回内容。字段一致的小型结果列表可按行查看，文本、图片和资源保持报告顺序。未识别的工具保留原名称和可读结果，完整输入输出在「技术详情」。
4. 工具权限、Claude 或 Cursor 的提问和 Cursor 计划审批都在输入框下方处理。工具审批会标出调用 ID、CLI 目录和每个选项的作用范围。若 CLI 没有随请求附上参数，可以展开 **查看最初的工具调用** 核对上下文。决定以本次请求为准。轨迹里的 **查看审批请求** 只读，不会再次授权。
5. 使用原停止按钮结束本轮或取消连接，已经输出的内容保留。
6. 继续提问会复用同一外部会话。切换具体模型、ACP 提供方或普通 DSH 模型，都使用原模型选择器。

**在原输入框选 CLI 命令：** 当前 Agent 连接且空闲时，在行首输入 `/`，再键入名称片段筛选。选中 CLI 分组里的 `/cli:名称` 只会插入命令标签；按提示填好参数再发送。发给 CLI 的是它公布的 `/名称 参数`，不会触发 DSH 的同名命令。草稿重载、CLI 重连或命令表更新后需要重新选择。命令只接受文本，原来的 CLI 选项面板仍可使用。

**分辨 CLI 提醒与审批：** 工具服务器启动失败、模型临时回退等提醒出现在收到它的那一轮。展开可看 CLI 的说明和接收时间。连接时和轮次间的提醒显示在输入框下方的 **CLI 会话提醒**；只列当前连接最近八条，断开后不会冒充新提醒。去外部会话记录可以核对已经收到的提醒。提示中的链接和命令都是纯文本，不会执行，也不需要点允许。

**整理项目里的会话：** 在「项目 → 项目会话」选择 **当前项目**，按需搜索后点 **批量归档会话**。勾选具体会话，按名称和 DSH 会话 ID 核对再确认。正在工作、等待回应或有工作树记录的会话不会在这里归档；使用单会话入口可另行核对工作树。每项都有结果，未更改的会话不影响其他项。要找回它们，切到已归档列表后点 **批量恢复会话**。恢复保留原身份，不自动启动 Agent 或重建工作树。

**查看上下文压缩：** 在执行轨迹里展开 **CLI 上下文压缩**，查看 CLI 保留的摘要、失败原因或它提供的压缩前后 token 数。如果未收到最终状态，旧轮次会标注“最后报告为进行中”。同一次压缩的后续回报更新原卡片，不会变成新的回复或审批。插件不会替你执行压缩。

**查看上下文和 token：** 输入框下方的 **CLI 上下文 · 最近报告** 只跟随当前 Agent 和选中的 CLI，不取代 DSH 原有的用量入口。展开可看占用、窗口大小、报告时间，以及 CLI 明确给出的模型和会话累计费用。要核对旧任务，到那一轮的执行轨迹看最后一次窗口报告和提示结束时的 **CLI 会话累计 token**。窗口占用不是账单，会话累计也不是单轮消耗；没报告就不填零。

**回答 CLI 的问题：** Claude Code 的 `AskUserQuestion` 会在 DSH 会话的请求卡片里等待回答。按题单选、多选或填写补充文字，有示例的选项可以展开查看；选填项可留空。只有点 **提交回答** 才发送填写的字段。**不回答** 和取消分别通知 CLI。工作台不会用表单回答代替工具审批。CLI 撤回的问题、只读窗口和历史记录都不能作答。表单回执只记处理结果；CLI 后续输出仍可能包含答案，请勿填写密码或令牌。

**查看执行计划：** 在执行轨迹里，支持新版 ACP 计划的 CLI 可以同时报告任务清单和方案正文。清单显示各步骤的状态与完成数；点方案标题查看 CLI 当时发回的 Markdown 原文，不自动加载文中的图片。若另有文件路径，可点 **查看当前文件**，它不是历史正文。CLI 撤回计划时只标明对应 ID 已移除，不算任务完成或审批同意。

**查看联网工具：** 展开 **网页搜索** 看查询、域名限制和按报告顺序列出的来源；点 **显示更多来源** 只展开本地记录。**抓取网页** 会把目标地址、要求提取的内容和工具回报分开，**页内查找** 会显示查找词。CLI 只报操作、不回传正文时，卡片会明确提示。展开卡片不会访问网页，也不会把助手回复拼成搜索命中。

首次选择 ACP 时可以直接发送消息，也可以点输入框下方的 **接续 CLI 会话**。列表使用当前 DSH 工作目录，不用手填路径。选择 **在这里接续** 只连接旧上下文，不发送任务；之后的第一条消息不会附上本页之前的 DSH 历史。如果它已经绑定另一个 DSH 会话，按钮会直接打开原会话。CLI 回放的前文可按需查看，不会被插成 DSH 的新消息。

要保留原对话并尝试另一条路线，在同一工作目录打开一个尚未绑定 CLI 的 DSH 会话，选择同一提供方，在 **接续 CLI 会话** 中点 **从副本继续**。只有 CLI 同时支持列出、复制和重新打开历史时才显示。副本从 CLI 已保存的最新记录开始，有独立 ID；原会话不变。创建副本不发送任务，接下来用原生输入框发给副本。它不复制工作树，也不能选择某条历史消息作为起点。

连接正常并开始聊天后不另占一行；需要你回应时显示审批，已断开时可只重新连接。本轮失败时先核对错误，再决定给新指令还是显式新建外部上下文。在原模型菜单点 **CLI 设置**，无需离开聊天即可调整 CLI 公布的模式和选项、运行 CLI 命令、查看用量或前文。普通 DSH 模型没有这项菜单。完整执行记录仍在 **ACP 工作台 → 活动**。

连接或修改 CLI 配置期间提交的消息会在原生队列中等待，不与配置请求竞争。

主模型选择器只显示你勾选并保存的模型，并兼容已有手动模型配置。选择具体模型后，插件在发送本轮任务前先请求 CLI 切换模型；切换被拒绝时，不会发送任务。`acp-cursor / default` 等 `CLI default` 选项仍保留，表示沿用 CLI 当前模型，不假定模型名称或上下文长度。

已选模型会携带 CLI 公布的说明、输入能力，以及已知的上下文和输出上限。主选择器显示 ACP、图片能力及已知上下文标签，设置页展示详细信息。未公布的容量或价格保持未知，不按模型名称猜测；输出上限是 CLI 信息，不代表插件另行设置了输出参数。更新后在 **ACP 工作台** 刷新一次模型即可补齐缓存信息，不改变已保存的勾选列表。

支持思考强度的模型使用原选择器内的强度控件。标准 ACP 使用该模型公布的 `thought_level` 配置；Cursor 完整变体中的 `reasoning_effort` 则映射到同模型、其他参数相同的已公布变体，不拼接新 ID，也不把候选变体自动加入主列表。强度设置在发送任务前完成，被拒绝时不发送提示词。`CLI default` 不提供独立强度覆盖，以免改变含义不明的当前模型配置。

Cursor 使用 CLI 公布的完整模型变体 ID，例如 `gemini-4-hydrogen[reasoning_effort=high]`。刷新目录与连接会话都使用变体协议，不宣告尚未实现的参数化选择器能力。更新插件后，已有连接需先断开再重连，新的能力协商才会生效。

执行记录中的 **CLI 命令** 会列出 Agent 公布的命令。选择命令并填写参数后，它作为普通用户消息进入当前原生时间线，但不经过 DSH 的斜杠命令解析器。原输入框中的 DSH `/...` 命令保持原行为。

**新建外部上下文** 会退役当前绑定，下一条输入创建新的远端会话。DSH 消息和旧执行记录保留，不删除文件或 CLI 历史。

## 用法二：由 DSH 委派

保留普通 DSH 模型，例如请求它使用 `subagent_cursor` 处理一项任务。

- bundle 通过官方 `@deepseek-ai/dsh-tool-subagent` 注册三个工具，并显式配置 ACP 子模型路由。Claude Code 的 ACP 入口是 `subagent_acp_claude_code`，与官方非 ACP 工具 `subagent_claude_code` 并存。升级后，如曾单独勾选旧 ACP 工具，请改选新名称。
- 子任务拥有真正的 DSH Session、名称和生命周期，不是一次性后台进程回执。
- 使用原生 `send_message` 续聊，使用原生子代理树查看状态和对话。
- 父会话输入框下方优先显示等你回应和进行中的子任务。审批卡片不用展开轨迹即可回答；已安静的子任务收在「其他子任务」，可以打开原会话或单独查看轨迹。
- 最终结果按 DSH 原生子代理机制交给父 Agent。父 Agent 不会因此自动获得子任务完整的思考和工具日志。
- 插件不修改已保存的预设或工具选择。如果工具没有出现，请在原工具选择器启用相应工具。

直接使用 ACP 引擎时，执行的是 CLI 自己的工具，不会自动获得 DSH 的 `subagent`、MCP 或文件工具。需要 DSH 编排时，应保留普通 DSH 主模型并使用委派模式。

## 上下文、恢复和附件

- 一个 DSH Session 与一个 ACP 提供方对应一个远端会话。同一 DSH 会话切换不同 ACP 提供方时，各自保留上下文。
- 首次交接把历史文本明确标记为上下文，不把历史工具输出当成系统指令。后续只把本次原生步骤接收的消息作为新任务；在其他引擎上完成的工作作为历史补充，不重新提交为任务。
- DSH 分叉创建独立远端会话，不复用父会话的远端 ID。
- 断开、原生 Session 重新打开或冷子任务续聊时，在 CLI 支持时使用 `session/resume` 恢复原 ID，不让 CLI 重播整段历史。首次接续旧会话优先用 `session/load` 读取前文；只支持 load 的 CLI 继续使用 load。两者均不支持时明确报错，不偷偷改建新会话。
- Host 重启不会自动重发不确定是否已经执行的输入。自动重试关闭；需要用户给出新的执行意图。
- 当前输入中的图片在 CLI 宣布支持图片时转发；返回图片存入 DSH 附件系统。普通文件通常已被 DSH 转换为只读本机文件路径，CLI 使用自己的文件工具读取；未转换的文件块使用 ACP resource link。
- 历史附件在文本交接中保留说明，不批量重新上传历史图片。非图片的二进制返回内容保留在原始事件中，原生回答给出提示。
- 一次文本交接最多 200,000 字符。超过限制明确拒绝，不静默截断。可先切回普通 DSH 模型压缩，或新建 DSH 会话。

## 设置与诊断

侧栏 **ACP 工作台** 分为两页：

- **提供方**：左侧列出提供方，右侧编辑显示名称、可执行文件和参数（已保存提供方的 ID 不可改，避免误建新提供方）。填写工作目录后可 **刷新模型**，再勾选候选模型并 **保存模型选择**，决定哪些模型出现在主选择器；也可 **检查能力**，结果按 Agent、协议版本、登录方式和能力标签（恢复会话、会话列表、图片/音频输入、MCP 等）展示，并保留原始结果；**查找 CLI 会话** 需要 CLI 支持 `session/list`，导入不会自动连接。
- **活动**（默认）：先列等你回应、进行中、需查看，再列最近活动。按提供方、名称、目录或会话 ID 搜索；归档及退役记录在「历史」。打开记录直接处理请求，或点「打开会话」回到原输入框。只有旧记录缺少直接父级地址时，才改为打开所属会话树。详情保留改名、配置、连接、停止与原始事件。重新连接不会重发原任务。

原始事件保留通知、stderr、请求应答、结束原因和提供方返回的数据。模型、模式及配置只采用 CLI 实际公布的值；不通过试着切换模型来探测目录。尚未接入 Cursor 私有模型目录 `cursor/list_available_models`。

`acp_workbench` 工具保留为高级兼容入口，支持旧式记录的 list/create/get/events/connect/prompt/cancel/disconnect/rename/archive/restore。不要用它替代原生委派：旧式 prompt 返回的是接收回执。绑定到 DSH 会话的记录对它只读（get/events），它不能发送任务、断开或归档这些记录，也不能批准交互或修改提供方/权限模式。

## 错误处理

- CLI 对一次提问或一次配置返回 JSON-RPC 错误（例如需要登录、额度不足、模式不可用）时，本轮或该设置失败并显示原因，但进程和远端会话保持连接，下一条消息无需重连。只有进程退出、输出损坏等传输故障才关闭连接。
- 返回图片无法存入 DSH 附件（如 SVG 或数据损坏）时，回答中改为一条指向原始事件的说明，本轮其余内容照常完成。
- Host 重启后，未完成的轮次标记为已中断，并补齐其事件范围，轨迹不会混入之后的轮次。

## 权限与限制

- **外部 CLI 使用自己的登录、计费、工具和文件权限，不受 DSH 工具 guard 或文件沙箱约束。** 插件只处理 CLI 实际发出的审批，不能保证所有操作都会询问。
- 只有所属会话明确使用完全访问预设且 CLI 公布 `allow_once` 时才可自动同意一次。只有持久授权选项时仍须人工选择；问题与计划始终交给人。执行轨迹标明自动或人工及所选选项。
- 不读取或复制 CLI 凭据，不抓取账号额度。仅显示实际返回的 usage；缺失不是零，也不是剩余额度。
- 不透传 DSH MCP，不宣告 ACP 客户端 filesystem / terminal 能力。外部 CLI 仍可管理自己的工具与 MCP。
- ACP 路由不是通用无状态补全模型。标题生成、DSH 压缩等辅助调用不会被偷换成外部任务；这些功能应使用普通 DSH 模型或已有的独立辅助模型配置。
- 不包含远程中继、移动客户端、自动 worktree、语音、独立终端或另一套 IDE。已有 DSH 功能不被替换。

## 数据与开发

DSH 保存原生消息；`acp_workbench` storage domain 保存绑定、配置和外部执行轨迹。历史可能包含源代码、工具输入输出及 CLI 日志，目前不自动裁剪。

事件按 64 条分块，流式尾部约 150 ms 合并写入；已写入的分块不再常驻内存，只缓存每条记录正在写的尾块。浏览器端所有面板共用一条实时连接。提示词与人工决定在发送前落盘；异常退出仍可能损失未刷盘的输出尾部。不确定投递不会自动重发。卸载会取消并等待插件拥有的操作和进程。

无需构建或新增运行时依赖。`native.js` 负责原生桥接，`manager.js` 负责 ACP 会话操作，`transport.js` 负责子进程 RPC，`store.js` 负责持久化，`client.js` 负责输入框下方的审批与子任务卡片、回答旁的执行轨迹和设置页，并复用 DSH 的界面组件（按钮、状态点、折叠行、diff 等）。接口与状态语义见 [DESIGN.md](./DESIGN.md)。

验证区分源码/语法检查、隔离确定性 ACP 端到端检查、真实 CLI 任务和浏览器实测。前两者通过不代表后两者已经验证。
