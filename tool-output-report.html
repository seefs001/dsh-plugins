“源头精简”＝字符串原文去包装 ＋ 单次 Git 汇总；“保守首屏”＝格式精简后按预算预览，完整保留规则和失败批次。二者是独立方案，不叠加。

04 THE FINE PRINT

数字可信，边界也要透明。

离线 · 无外部依赖
/ 01

统计的是可见输出，不是账单

同一组 45 次历史返回，每次只计一次。使用 DSH 的固定密度估算器：文本 UTF-16 长度 ÷ 4，再加结构开销。只计实际保留的内容，不把已截掉的原始大输出加回来。

/ 02

源头精简与预算模拟分开

159 处字符串按原文展开，不删源码与诊断；另把一批 Git 状态改为摘要。Git 子输出为 659 tokens，含文件发现及完整历史结果位置的整批为 704 tokens。

/ 03

没有把“后移”冒充“消除”

预算模拟让部分内容延后读取，不等于任务已经完成。新增规则约增加 191 个估算 tokens 的固定输入；后续补读、重复输入、缓存与实际计费均未折算。

这份报告没有证明：完整任务会净省 46%–60%，Rust CLI 的执行速度提升了多少，或提示词本身一定让模型选对命令。下一步应在可比任务中测量完整结果、补读次数与总输入成本，而不是只追求更短的首屏。
