## 环境要求

| 依赖 | 要求 |
| --- | --- |
| DeepSeek Harness | `>=0.2.2-rc.1 <0.3.0`，部分插件要求 rc.2，见 [版本与边界](/docs/compatibility) |
| Node.js | `^22.19.0` 或 `>=24` |
| 浏览器界面 | 带 Web 部分的插件需要 `dsh web` |

下文命令以 `web` profile 为例。安装时用的 profile 必须和你实际启动的 profile 一致。

## 从 GitHub 安装

<Steps>
<Step>

### 选一个插件

在 [插件目录](/docs/plugins) 里找到插件，记下目录名，例如 `model-reference`。

</Step>
<Step>

### 安装

<InstallCommand slug="model-reference" />

`path:` 指向本仓库里的一个包，只会安装这一个插件，不需要构建。也可以打开 Web 界面的 **Plugins** 页，粘贴 `github:` 开头的地址。

</Step>
<Step>

### 确认生效

安装成功后，Plugin Manager 会选中这个 bundle。profile 启用了 HMR 时，改动立即生效，结果显示 `applied`。结果是 `restart-required` 时，重启这个 profile 的 DSH。Web 部分的更新在刷新页面后加载。

</Step>
</Steps>

`#main` 安装的是 GitHub `main` 分支上已经推送的版本。要试本地还没推送的改动，用下面的 `link:` 方式。

## 从本地仓库安装

```bash
git clone https://github.com/seefs001/dsh-plugins.git
cd dsh-plugins
dsh plugin --profile web add link:$PWD/packages/model-reference
```

`link:` 让 profile 直接使用仓库里的源码。修改后的加载方式见 [开发与发布](/docs/development)。

## 一次装多个

按用途分组的全部命令，可以只复制需要的行：

<InstallAll />

<Callout type="warn" title="先确认额外依赖">
有些插件需要先启用别的 bundle 或准备外部条件，例如 Auto review、Change requests & worktrees、Responses provider、macOS 或特定的 DSH 构建。安装前看一下 [版本与边界](/docs/compatibility) 的表格。
</Callout>

## 安装后没有变化

- 确认安装用的 profile 就是正在运行的 profile，并在 Plugins 页确认 bundle 已启用、没有报错。
- Plugin Manager 返回 `restart-required` 时，重启后再看。
- Web 部分在刷新页面后才会加载新代码。
- 有些入口只在特定场景出现：⚡ 只出现在 `openai-responses` 模型旁；子代理模型只在子代理会话里显示；Git 变更需要 Git 仓库和 Change requests & worktrees；AI 吉祥物只在 GPT 或 Claude 模型的对话里出现。
- 插件声明的 `engines.dsh` 不包含当前 DSH 版本时，Plugin Manager 会拒绝安装。

## 移除

在 Plugins 页停用或移除对应 bundle，或在命令行运行：

```bash
dsh plugin --profile web remove dsh-model-reference
```

移除插件不会删除它在 Host 存储里留下的数据，例如会话分组或审查日志。各插件页的“数据”一节写明了这些数据的位置。
