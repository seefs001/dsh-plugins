## 环境准备

在仓库根目录安装依赖：

```bash
pnpm install
```

## 目录结构

```text
packages/<name>/
├── package.json        # name = dsh-<name>, dsh.bundle, 可选 dsh.client
├── cordis.patch.yml    # bundle patch，至少插入 dsh-<name> 行
├── lib/index.js        # Host 入口（纯 ESM，无需构建）
├── src/client.js       # 浏览器端可读源码（可选懒分包 src/client.<chunk>.js）
├── lib/client.js       # 浏览器端压缩产物（由 src/client.js 确定性生成）
├── locale/{en,zh}.json # Plugins 页面展示的 meta.title 与 meta.description
├── icon.svg
├── test/*.test.js      # node:test 单元测试
└── README.md
```

## 客户端源码与构建工作流

Host 端代码（`lib/*.js`）为无需构建的原生 ES 模块。浏览器端完整可读源码统一保存在 `packages/<name>/src/client.js`（以及通过 `require.async('./client.page.js')` 按需加载的 `src/client.page.js`），提交到仓库的 `lib/client*.js`（`pi-tools` 为根目录 `client.js`）由 `scripts/build-clients.mjs` 调用仓库锁定的 `esbuild`（`minify: true, target: 'es2022', legalComments: 'none'`）确定性压缩生成：

```bash
pnpm run build:clients        # 从所有包的 src/client*.js 重新生成压缩后的客户端产物
pnpm run build:clients:check  # 逐字节核对压缩产物与 src/client*.js 是否完全一致
```

本地 `pnpm run check` 与 GitHub Actions CI（`.github/workflows/ci.yml`）都会强制执行 `pnpm run build:clients:check`，确保仓库中的压缩产物始终可由开源 `src/client*.js` 精确重现，不存在与源码脱节的产物。修改浏览器端代码时，请编辑 `src/client*.js`，再运行 `pnpm run build:clients` 刷新页面生效。

以下 4 个包还包含额外的专用构建步骤：

- `canvas`：修改 `src/` 下画布运行时代码后运行 `pnpm --filter dsh-canvas build` 重新打包 `lib/client.runtime.js`。
- `diagram-preview`：升级图表库后运行 `pnpm --filter dsh-diagram-preview build` 重新生成懒加载渲染器分片。
- `pi-tools`：浏览器端压缩产物在根目录 `client.js`（由 `pnpm run build:clients` 从 `src/client.js` 生成）；改动 Go runner 或 Pi 依赖后运行 `pnpm --filter dsh-pi-tools build:runner:all`。
- `message-actions`：由自身构建脚本打包 `src/` 生成 `lib/client.js` 与 `lib/client.markdown.js`，运行 `pnpm --filter dsh-message-actions build`。

## 静态检查与测试

```bash
pnpm run check     # build:clients:check + oxlint + validate.mjs + node:test
pnpm run pack:dry  # 演练所有包的 npm pack
```

检查链路强制执行以下规则：

- **Oxlint（`.oxlintrc.json` + `scripts/oxlint-plugin.mjs`）**：
  - `correctness` 与 `suspicious` 均为 error，`--deny-warnings`；
  - `dsh/no-comments`：禁止注释，仅放行 shebang、文件头开源协议声明、单行 URL 与单行 `// external: <原因>`（记录不可改动的外部依赖或宿主限制）；
  - `dsh/no-suppression-comments`：禁止 `oxlint-disable`、`eslint-disable`、`@ts-ignore`、`@ts-expect-error`、`@ts-nocheck`；
  - `dsh/no-legacy-compat`：禁止残留旧版兼容标识。
- **清单与文档校验（`scripts/validate.mjs`）**：
  - 校验包名、版本、目录、`engines.dsh`、`files`、`exports`、`cordis.patch.yml`、`dsh.client` 与 `locale/{en,zh}.json`；
  - 校验 `apps/docs/lib/plugins.ts`、`apps/docs/content/docs/plugins/*.mdx`、`meta.json` 与根目录 `README.md` / `README.zh.md` 同步。

## 文档站

```bash
pnpm run docs:dev        # 本地预览（http://localhost:3000）
pnpm run docs:typecheck  # fumadocs-mdx + next typegen + tsc
pnpm run docs:build      # 静态导出到 apps/docs/out
```

新增插件时，在 `apps/docs/lib/plugins.ts` 添加目录项、在 `apps/docs/content/docs/plugins/` 新增 `.mdx` 文件并加入 `plugins/meta.json`。
