## 环境准备

在仓库根目录使用根 `package.json` 指定的 `pnpm` 版本安装依赖：

```bash
pnpm install
```

## 包目录结构

```text
packages/<name>/
├── package.json        # name 必须为 dsh-<name>，含 dsh.bundle 与可选 dsh.client
├── cordis.patch.yml    # bundle patch，至少插入名为 dsh-<name> 的行
├── lib/index.js        # Host 入口（ESM）
├── lib/client.js       # 可选浏览器入口（window.__ModuleLoader__.load）
├── locale/{en,zh}.json # Plugins 页面显示的 meta.title 与 meta.description
├── icon.svg            # 包图标
├── test/*.test.js      # node:test 单元测试（可选）
└── README.md           # 包说明文档
```

绝大多数插件都是无需构建的原生 ES 模块，`link:` 安装即直接执行源码。两个例外：

- `pi-tools`：浏览器入口位于包根目录 `client.js`，`cordis.patch.yml` 同时挂载 `work-timeline` 与完整的 `pi` 预设。
- `message-actions`：浏览器源码位于 `src/client.js`，需执行 `pnpm --filter dsh-message-actions build` 生成 `lib/client.js`（`prepack` 会自动运行）。

## 本地链接调试

```bash
dsh plugin --profile web add "link:$PWD/packages/model-reference"
```

在 **Plugins** 页面确认 bundle 已开启。若 profile 开启了 HMR，改动会触发重组合；若返回 `restart-required` 则重启 DSH 进程。浏览器部分刷新页面后生效。

## 静态检查与测试

```bash
pnpm run check     # 依次运行 oxlint + validate.mjs + node:test
pnpm run pack:dry  # 演练所有包的 npm pack
```

`pnpm run validate` 会强制校验：

- 包名为 `dsh-<目录名>`，`repository.directory` 匹配目录，`type` 为 `module`，`keywords` 含 `dsh-plugin`，且声明了 `engines.dsh`；
- `dsh.bundle.patch` 文件存在，且插入了同名条目；
- 所有 `exports` 指向真实文件；仅当声明 `dsh.client` 时导出 `./client`，且其 `id` 与包名一致；
- `locale/en.json` 与 `locale/zh.json` 存在、`meta` 键一致且含 `title` 与 `description`；
- `README.md` 与 `icon.svg` 均存在。

## 文档站开发

```bash
pnpm run docs:dev        # 启动本地预览（http://localhost:3000）
pnpm run docs:typecheck  # 运行 fumadocs-mdx、next typegen 与 tsc
pnpm run docs:build      # 静态导出到 apps/docs/out
```

| 路径 | 职责 |
| --- | --- |
| `apps/docs/content/docs/**/*.mdx` | 文档正文（frontmatter 必须有 `title` 与 `description`） |
| `apps/docs/content/docs/**/meta.json` | 侧边栏分组与排序 |
| `apps/docs/lib/plugins.ts` | 登记插件分类、简介、运行位置与依赖；包名和标题在构建时自动从 `packages/*` 读取 |
| `apps/docs/components/plugins.tsx` | 提供 `<PluginFacts>`、`<InstallCommand>`、`<PluginDirectory>`、`<RequirementsTable>` 等 MDX 组件 |
| `apps/docs/app/page.tsx` | 文档站首页 |

新增插件时必须在 `apps/docs/lib/plugins.ts` 添加记录、在 `apps/docs/content/docs/plugins/` 新建 `.mdx` 文件并列入 `plugins/meta.json`，否则构建会直接报错失败。

## 发布包

1. 更新 `packages/<name>/package.json` 的 `version` 并在 `CHANGELOG.md` 补充记录。
2. 运行 `pnpm run check` 确保全部通过。
3. 在对应包目录执行 `npm publish`。

文档站通过独立工作流部署到 GitHub Pages，见 [GitHub Pages 部署](/docs/deployment)。
