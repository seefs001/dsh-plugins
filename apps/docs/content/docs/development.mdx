## 准备

在仓库根目录安装依赖。包管理器是根 `package.json` 的 `packageManager` 字段指定的 pnpm 版本，Node.js 要求 `^22.19.0` 或 `>=24`。

```bash
pnpm install
```

## 包结构

```text
packages/<name>/
├── package.json        # name = dsh-<name>，dsh.bundle，可选的 dsh.client
├── cordis.patch.yml    # bundle patch，至少插入一行 name = dsh-<name>
├── lib/index.js        # Host 入口，原生 ES 模块
├── lib/client.js       # 可选的浏览器入口（window.__ModuleLoader__）
├── locale/{en,zh}.json # Plugins 页的 meta.title 和 meta.description
├── icon.svg
├── test/*.test.js      # 已有的 node:test 测试（不是每个包都有）
└── README.md
```

大多数插件是不需要构建的纯 JavaScript，`link:` 安装直接运行源码。例外：

- `pi-tools` 的浏览器入口在包根目录的 `client.js`，patch 除了自己的行，还插入一个 `pi` Agent 预设。
- `message-actions` 的浏览器源码在 `src/client.js`，用 `pnpm --filter dsh-message-actions build` 打包成 `lib/client.js`，`prepack` 会自动构建。
- `switchboard` 的 `lib/vendor/switchboard-kit.js` 由 switchboard 仓库生成。

## 链接本地插件

```bash
dsh plugin --profile web add link:$PWD/packages/model-reference
```

在 Plugins 页确认 bundle 已启用。profile 启用了 HMR 时，Plugin Manager 和 HMR 的重新组合会替换文件已变化的插件；否则按 Plugin Manager 返回的 `restart-required` 重启 DSH。浏览器部分刷新页面后加载。

## 检查

```bash
pnpm run check     # oxlint + manifest 校验 + node:test
pnpm run pack:dry  # 只检查 packages/* 的 npm 打包内容
```

`pnpm run validate` 检查：

- 包名是 `dsh-<目录名>`，`repository.directory` 指向包目录，`type` 是 `module`，`keywords` 包含 `dsh-plugin`，设置了 `engines.dsh`。
- `dsh.bundle.patch` 存在，并插入名为包名的行。
- 每个导出都指向存在的文件；只有声明了 `dsh.client` 才导出 `./client`，并且浏览器 bundle 的 ID 等于包名。
- `en` 和 `zh` locale 都存在，`meta` 键一致，并且都有 `meta.title` 和 `meta.description`。
- 有 README 和图标。

这些检查覆盖源码和包元数据。界面效果需要在装了插件的 DSH 里实际查看。

## 维护文档

```bash
pnpm run docs:dev        # http://localhost:3000
pnpm run docs:typecheck  # fumadocs-mdx、next typegen 和 tsc --noEmit
pnpm run docs:build      # 静态导出到 apps/docs/out
```

| 位置 | 内容 |
| --- | --- |
| `apps/docs/content/docs/**/*.mdx` | 页面正文，frontmatter 必须有 `title`，建议写 `description` |
| `meta.json` | 侧边栏顺序和分组 |
| `apps/docs/lib/plugins.ts` | 插件的分组、一句话简介、运行位置和额外要求 |
| `apps/docs/components/plugins.tsx` | 插件信息框、目录、版本表和安装命令 |
| `apps/docs/app/page.tsx` | 首页 |

插件的版本、DSH 范围和中文标题在构建时从 `packages/*/package.json` 和 `locale/zh.json` 读取，不要在页面里手写。新增插件时，在 `lib/plugins.ts` 加一条记录并新建 `content/docs/plugins/<name>.mdx`，再把它加进 `plugins/meta.json`。漏掉记录时文档构建会失败。

修改插件行为时，同时更新包的 README 和站点上的插件页。

## 发布插件

1. 修改包的 `package.json` 里的 `version`，在 `CHANGELOG.md` 加一条。
2. 运行 `pnpm run check`。
3. 在包目录运行 `npm publish`。

文档部署是独立的工作流，见 [GitHub Pages](/docs/deployment)。
