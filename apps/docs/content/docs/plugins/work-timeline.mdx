<PluginFacts slug="work-timeline" />

在输入框上方摘要条与右侧详情面板中展示会话级的工作计划、修订历史和关联产物（交付物与证据文件），在 `pi` 预设中替代传统扁平的 TODO 清单。

<Callout type="info" title="工具与界面拆分">
本包的主入口提供投影与右侧面板视图；`work_read` 与 `work_update` 工具由子入口 `dsh-work-timeline/tools` 提供，已默认挂载在 [Pi 工具](/docs/plugins/pi-tools) 的 `pi` 预设中。
</Callout>

## 界面视图

- **输入框摘要条**：显示当前工作标题、完成进度、受阻项数量及下一步任务，点按打开右侧详情面板。
- **计划**：查看所有步骤状态（待开始 / 进行中 / 受阻 / 已完成 / 已取消）、受阻原因与阶段结果。
- **过程**：按修订号（`revision`）回看每轮调整原因及步骤/产物的增删改明细（保留最近 20 次修订，支持标识从分叉前继承的工作）。
- **产物**：按步骤过滤 `deliverable`（交付物）和 `evidence`（证据），点击文件直接在文件侧栏打开当前磁盘上的文件。

## 数据与边界

- 状态直接随会话日志里成功的 `work_update` 工具结果（`meta.dshWorkTimeline`）保存，不使用单独的 storage domain。
- `work_update` 带有 `expectedRevision` 并发保护，需由模型直接调用（禁止在 `codemode` 脚本内嵌套调用）。
- 仅反映 Agent 主动汇报的进展，不自动执行工作流，也不替代权限审批、`exit_plan_mode` 或 Goal。
