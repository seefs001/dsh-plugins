<PluginFacts slug="pi-tools" />

为 DSH 新增独立的 **`pi`** Agent 预设，把 Pi 编程工具、系统提示词和 MoeJS `codemode` 沙箱接入 DSH 的会话、权限、沙箱、模型路由与 MCP 体系中，不影响默认预设和其他会话。

<Callout type="info" title="环境要求与扩展">
运行环境中需提供 `rg` 与 `fd`（也可通过 `rgCommand` / `fdCommand` 指定路径）。需要计划时间线和产物面板时，另行启用[工作时间线](/docs/plugins/work-timeline)，`pi` 预设会自动接入。
</Callout>

## 安装

<InstallCommand slug="pi-tools" />

安装后在「新建会话」选择 **`pi`** 预设即可使用。

## 预设包含的工具

<Tabs items={['Pi 编程工具', '挂载的 DSH 能力', '会话工具选择器与 MCP']}>
<Tab value="Pi 编程工具">

- **文件与命令行**：`read`、`bash`、`edit`、`write`、`ls`、`find`、`grep`，保持 Pi 的工具名、描述与参数格式，底层受 DSH 的 `ctx.fs`、`ctx.subprocess` 和 `ctx.sandbox` 约束。`find` 中含 `/` 的模式（如 `src/*.ts`、`./src/*.ts`）锚定在搜索根目录，匹配任意层级使用 `**/src/*.ts`；不含 `/` 的模式（如 `*.ts`）匹配所有层级。
- **`codemode`**：常驻 Go 子进程运行 MoeJS 沙箱，每次脚本独享一个 runtime，支持 `Promise.allSettled`、`store` / `load`、`ALL_TOOLS`、`searchTools`、`describeTool` 与 `describeNamespace`。脚本无 Node、文件系统或直连网络 API，所有外调均经由当前步的 DSH 工具管线。
- **回传预算**：默认整批文本保留约 8,000 字符；超出时保留首尾并将完整文本写入返回路径，可用 `read` 分段查看。图片照常返回；可在脚本首行设置 `// @options: {"max_output_tokens": 4000}` 调整单次预算。
- **编辑差异与实时轨迹**：成功的 `edit` 在直接调用和 `codemode` 子步骤中均可通过「编辑差异」查看增删行；`codemode` 子步骤默认折叠，折叠时仍显示执行进度和失败步数。
- **`tool_search`**：BM25 工具检索，命中后从下一轮请求起成为直接可调用工具。
- **Skill 正文提醒**：请求前追踪哪些 Skill 的完整指令仍留在上下文中，正文被裁剪或压缩移除后自动更新名单。
- **请求适配**：在兼容路由上恢复 `constrainedSampling`；孤立的 `SyntaxError` / `ReferenceError` 会附带 `String.raw` 等转义指引；`anthropic-messages` 中继将纯工具结果误报为 `assistant message prefill`（HTTP 400）时自动重试一次该请求，不重跑工具。

</Tab>
<Tab value="挂载的 DSH 能力">

`cordis.patch.yml` 在 `pi` 预设内独立挂载以下 DSH 原生能力：

| 类别 | 工具与功能 |
| --- | --- |
| 工作与计划 | 独立 `planMode`（`exit_plan_mode`）；启用工作时间线后自动挂载 `work_read`、`work_update` |
| 子代理与提问 | `subagent`、`subagent_fork`、`list_subagent_models`、`send_message`、`list_agents`、`wait_agent`、`ask_user_question` |
| 技能、目标与任务 | `skill`、`workflow`（DSH PTC）、`job_*`、`schedule_*`、`create_goal` / `get_goal` / `update_goal`、`/goal` |
| 联网、展示与扩展 | `web_fetch`、`web_search`，以及按需勾选的 `present`、`office_*`、`plugin_manager`、`plugin_market`、`cordis_inspect`、`session_lifecycle` |
| 全局工具透传 | `grok_search`、`openai_search`、`openai_image`、`grok_image`、`subagent_antigravity`、`subagent_cursor`、`subagent_acp_claude_code`、`session_lifecycle` |
| 上下文管理 | `tool-result-pruner` 与 `compaction-basic`（可通过 `DSH_PI_SUMMARY_PROVIDER` / `DSH_PI_SUMMARY_MODEL` 指定摘要模型） |

</Tab>
<Tab value="会话工具选择器与 MCP">

在空白 `pi` 会话中点击 **Tools** 打开选择器（首轮开始后锁定）：

- **精简视图 / 逐个设置**：按 Pi、DSH 分类与 MCP 服务分组勾选，支持 **只看已保留** 与 **恢复默认**。
- **设为默认**：将当前勾选与默认规则的差异存入 Host 的 `pi_tools_defaults` storage domain，对之后新建的 `pi` 会话生效。
- **刷新 MCP**：重启已桥接的 DSH MCP 服务器（最多等待 20 秒）并刷新工具目录。配合 [Pi MCP 服务器](/docs/plugins/pi-mcp) 使用时，修改 `~/.pi/agent/mcp.json` 后可在此直接刷新。

</Tab>
</Tabs>

## 配置与边界

- 默认配置 `mcpServers: ['*']`、`mcpExposure: codemode`、`maxParallel: 10`，将全局 DSH MCP 工具收入 `codemode` / `tool_search` 延迟发现目录。
- 所有工具（包括 `codemode` 内嵌套调用）均遵守 DSH 原生权限、沙箱与当前步条件（如 `planMode` 限制）。
- 会话工具选择写入会话日志的 `plugin:dsh-pi-tools/selection`；更新插件后新建 `pi` 会话即可应用新配置。
