<PluginFacts slug="pi-tools" />

为 DSH 新增一个独立的 **`pi`** Agent 预设：把 Pi 原版的编程工具、系统提示词与 QuickJS `codemode` 沙箱接入 DSH 原生的会话、权限、沙箱、模型路由和 MCP 连接中，同时完全保留默认预设和其他会话不变。

<Callout type="info" title="环境要求与联动">
运行环境中需提供 `rg` 与 `fd`（也可通过配置 `rgCommand` / `fdCommand` 指定路径）。安装本包时会自动一并启用 [工作时间线](/docs/plugins/work-timeline) 作为 `pi` 预设的计划与产物工具。
</Callout>

## 安装

<InstallCommand slug="pi-tools" />

安装后在「新建会话」页面选择 **`pi`** 预设即可使用。

## 预设包含哪些工具

<Tabs items={['Pi 原版工具', '挂载的 DSH 能力', '会话工具选择器与 MCP']}>
<Tab value="Pi 原版工具">

- **文件与命令行**：`read`、`bash`、`edit`、`write`、`ls`、`find`、`grep`，保持 Pi 原版名称、描述与参数格式，底层全部受 DSH 的 `ctx.fs`、`ctx.subprocess` 和 `ctx.sandbox` 约束（如写入符号链接目标时会按 DSH 规则替换）。
- **`codemode`**：Pi 的 QuickJS Worker 沙箱（仅接受 `{ code: string }`），脚本内可使用 `Promise.allSettled`、`store` / `load`、`ALL_TOOLS`、`searchTools`、`describeTool` 与 `describeNamespace`。脚本无 Node、文件系统或直连网络 API，所有动作均经过当前步受控 DSH 工具管线。
- **回传预算**：默认整批文本保留约 8,000 个字符。超出时保留首尾，完整文本写入返回路径，可用 `read` 分段查看，无需重跑。图片仍正常返回；要调整单次预算，在脚本首行设置 `// @options: {"max_output_tokens": 4000}`。
- **Skill 正文提醒**：Pi 在请求前提示哪些 Skill 的完整指令仍可见。目录、失败调用和未返回正文的 `codemode` 调用不算；重复加载不重复发布名单，正文被裁剪或压缩移除后更新提醒。
- **实时轨迹**：`codemode` 内的工具调用在开始执行时就显示参数。例如 `tools.bash` 会先显示命令，结束后在同一条记录上显示结果，不必等整个脚本返回。
- **`tool_search`**：Pi 的 BM25 工具检索，命中后从下一轮模型请求起变为直接可调用工具。
- **语法采样与恢复**：通过 `lib/pi-ai-hook.js` 在兼容路由上恢复 `constrainedSampling`（其他路由沿用 JSON `{ code }`），并在无嵌套调用的孤立 `SyntaxError` / `ReferenceError` 中附带 `String.raw` 等修正指引。

</Tab>
<Tab value="挂载的 DSH 能力">

`cordis.patch.yml` 在 `pi` 预设内部独立挂载以下 DSH 原生能力：

| 类别 | 工具与功能 |
| --- | --- |
| 工作与计划 | `work_read`、`work_update`（取代 `todo_write`）；独立 `planMode`（`exit_plan_mode`） |
| 子代理与提问 | `subagent`、`subagent_fork`、`list_subagent_models`、`send_message`、`list_agents`、`wait_agent`、`ask_user_question` |
| 技能、目标与任务 | `skill`（含 `/` 补全）、`workflow`（DSH PTC）、`job_*`、`schedule_*`、`create_goal` / `get_goal` / `update_goal`、`/goal` |
| 联网、展示与扩展 | `web_fetch`、`web_search`、可选启用 `present`、`office_*`、`plugin_manager`、`plugin_market`、`cordis_inspect_*` |
| 全局工具透传 | `grok_search`、`openai_search`、`openai_image`、`grok_image`、`subagent_agy`、`subagent_cursor` |
| 上下文管理 | 工具结果裁剪（超过 8,192 字符保留首尾）与文本压缩（可设 `DSH_PI_SUMMARY_PROVIDER` / `DSH_PI_SUMMARY_MODEL` 环境变量指定摘要模型） |

</Tab>
<Tab value="会话工具选择器与 MCP">

在尚未开始第一轮的空白 `pi` 会话中点击 **Tools** 打开选择器（首轮开始后锁定）：

- **简洁视图 / 逐工具视图**：按 Pi、DSH 分类与 MCP 服务分组筛选勾选，支持 **仅看已选** 与 **恢复默认**。
- **设为默认**：将当前勾选与默认规则的差异保存到 Host 的 `pi_tools_defaults` storage domain，对之后新建的 `pi` 会话生效（不影响后续新加入的 MCP 工具按默认规则自动出现）。
- **刷新 MCP**：重启已桥接的 DSH MCP 服务器（最多等待 20 秒）并重新加载新工具列表。配合 [Pi MCP 服务器](/docs/plugins/pi-mcp) 使用时，修改 `~/.pi/agent/mcp.json` 后可在此直接刷新。

</Tab>
</Tabs>

## 边界说明

- 默认配置 `mcpServers: ['*']`、`mcpExposure: codemode`、`maxParallel: 10`，将全局 DSH MCP 工具默认收入 `codemode` / `tool_search` 延迟发现目录。
- `codemode`、`tool_search`、`work_update` 等工具均遵守 DSH 原生权限、沙箱与当前步条件（例如 Office 工具需先加载对应技能，`planMode` 下不允许越权执行写操作）。
- 选中工具后记录写入会话日志的 `plugin:dsh-pi-tools/selection`，更新包后需新开 `pi` 会话才会应用新版预设配置。
