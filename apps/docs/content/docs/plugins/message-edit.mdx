<PluginFacts slug="message-edit" />

把鼠标移到自己发过的消息上，点 Copy 旁边的铅笔图标，改完文字后直接保存。默认覆盖当前会话的模型上下文，不新建或切换会话。图片和文件留在原位，只有文字会被替换。

| 模式 | 效果 |
| --- | --- |
| **覆盖当前会话**（默认） | 在当前会话的模型上下文里原地改写这条消息，默认勾选 **清空后续上下文**，从模型上下文中移除之后的所有消息和工具结果；取消勾选则保留。不切换会话，也不会重新回答，已执行的操作不会撤销。原消息气泡直接显示保存后的文字，旁边标记 **已编辑**；复制按钮也复制修改后的文字。 |
| **分叉并重发**（主动选择） | 从这条消息之前的最后一个已完成轮次分叉，把改过的内容发到新会话并打开它。原会话完全不变；分叉前缀逐字节一致，provider 的 prompt 缓存仍然命中。 |

## 安装

<InstallCommand slug="message-edit" />

需要 Web 界面。

## 使用

1. 鼠标移到自己的消息上，消息底部出现铅笔按钮。
2. 点开对话框修改文字，默认选中 **覆盖当前会话**，并勾选 **清空后续上下文**。点击 **保存并清空后续上下文**；如果要保留后面的内容，取消勾选，再点击 **保存到上下文**。保存后留在原会话，原消息气泡更新为编辑后的文字，旁边显示 **已编辑** 标记。
3. 只有主动选择 **分叉并重发**，再点击 **分支并发送**，才会另建会话并跳过去，原会话留在列表里。

内容为空时提示无法提交；取消清空时，文字没改也不提交；勾选清空时，即使文字没改，也可以清空后续上下文。消息已被压缩或清空后，对话框会说明无法再原地改写，不会自动切换到分叉模式；前面没有任何历史时，也提供不了分叉。

## 两种模式的实现

- 浏览器部分接管 `conversation.chat.node` 的 `user` 渲染，按 `source.rpcId` 读取已保存的修改，复用 DSH 的 `conversation.chat.user.content` 渲染消息文字、图片和文件。复制与编辑按钮由插件提供，仍保留消息上方的装饰插槽，不直接修改其他组件的 DOM。
- 覆盖模式在 Host 上追加一条带 `surfaceOp: { op: 'replace' }` 的 `user/message`，默认替换从当前消息到末尾的全部上下文节点；取消清空时只替换当前消息，并且走 `agent.runMaintenance()`，不会和正在跑的轮次抢写。这和上下文压缩、工具结果裁剪用的是同一套核心机制，所以卸载插件后会话仍然可读。
- 只有主动选择分叉模式，浏览器才调用 `sessions.fork({ atSeq })` 建分叉，再由 Host 在新会话上发一次 followup。
- 浏览器只调用带 owner 认证的 `POST /message-edit/op`，不直接改会话日志。

## 限制

- 覆盖模式要求 Agent 空闲，正在运行的轮次要先停止。
- 消息被压缩或从上下文中清空后，覆盖模式拒绝执行，不会自动分叉。
- 插件启用时，原消息气泡和复制按钮使用编辑后的文字，刷新页面后仍会读取已保存的修改。禁用插件后，内置渲染器恢复显示原文，但模型上下文里的修改仍然保留。
- 清空只作用于模型上下文，后续聊天历史仍可见，也不会撤销已经执行的工具操作。
- 只有你自己输入的消息（source 类型 `user`）才有这个控件；steering 行、注入的上下文和定时提示词没有。
- 覆盖模式会让 provider 的 prompt 缓存从这条消息起失效。
