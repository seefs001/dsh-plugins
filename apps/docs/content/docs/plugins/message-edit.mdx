<PluginFacts slug="message-edit" />

把鼠标移到自己发过的消息上，点 Copy 旁边的铅笔图标，改完文字后在两种模式里选一个。图片和文件留在原位，只有文字会被替换。

| 模式 | 效果 |
| --- | --- |
| **清理后续消息** | 在去掉这条消息后的最后一条已完成消息处分支，把改过的内容发到新会话并打开它。原会话完全不变；分支前缀逐字节一致，provider 的 prompt 缓存仍然命中。 |
| **保留后续消息** | 只在当前会话的模型上下文里原地改写这条消息，后续消息保留，不会重新回答。聊天里仍显示原来的气泡，旁边是 **Edited in context** 标记，展开可以看到模型现在读到的内容。 |

## 安装

<InstallCommand slug="message-edit" />

需要 Web 界面。

## 使用

1. 鼠标移到自己的消息上，消息底部出现铅笔按钮。
2. 点开对话框修改文字，两个模式各有一行说明和一个提交按钮：**清理后续消息** 对应 **Branch and send**，**保留后续消息** 对应 **Save to context**。
3. 清理模式会新建会话并跳过去，原会话留在列表里；保留模式留在当前会话，气泡下方多出 **Edited in context** 标记。

内容为空时提示无法提交，文字没改时也不提交。消息已被压缩后，对话框会说明无法再原地改写；前面没有任何历史时，也提供不了分支。

## 两种模式的实现

- 浏览器部分把按钮挂进气泡自己的操作行，复用 Copy 按钮的样式；找不到那一行时不显示按钮。
- 清理模式由浏览器调用 `sessions.fork({ atSeq })` 建分支，再由 Host 在新会话上发一次 followup。
- 保留模式在 Host 上追加一条带 `surfaceOp: { op: 'replace' }` 的 `user/message`，只作用于那一个节点，并且走 `agent.runMaintenance()`，不会和正在跑的轮次抢写。这和上下文压缩、工具结果裁剪用的是同一套核心机制，所以卸载插件后会话仍然可读。
- 浏览器只调用带 owner 认证的 `POST /message-edit/op`，不直接改会话日志。

## 限制

- 保留模式要求 Agent 空闲，正在运行的轮次要先停止。
- 消息被压缩后，保留模式拒绝执行。
- DSH 的聊天只渲染追加的消息，单个会话没法在视觉上丢掉后续消息，所以清理模式改用分支。
- 只有你自己输入的消息（source 类型 `user`）才有这个控件；steering 行、注入的上下文和定时提示词没有。
- 保留模式会让 provider 的 prompt 缓存从这条消息起失效。
