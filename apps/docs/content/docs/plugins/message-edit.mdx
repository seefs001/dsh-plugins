<PluginFacts slug="message-edit" />

把鼠标移到自己发过的消息上，点 Copy 旁边的铅笔图标，改完文字后直接保存。默认覆盖当前会话的模型上下文，不新建或切换会话。图片和文件留在原位，只有文字会被替换。

| 模式 | 效果 |
| --- | --- |
| **覆盖当前会话**（默认） | 在当前会话的模型上下文里原地改写这条消息，后续消息保留，不切换会话，也不会重新回答。聊天里保留原来的气泡，旁边是 **上下文已修改** 标记，保存后展开修改预览。 |
| **分叉并重发**（主动选择） | 从这条消息之前的最后一个已完成轮次分叉，把改过的内容发到新会话并打开它。原会话完全不变；分叉前缀逐字节一致，provider 的 prompt 缓存仍然命中。 |

## 安装

<InstallCommand slug="message-edit" />

需要 Web 界面。

## 使用

1. 鼠标移到自己的消息上，消息底部出现铅笔按钮。
2. 点开对话框修改文字，默认选中 **覆盖当前会话**，点击 **保存到上下文**。保存后留在原会话，气泡旁出现 **上下文已修改** 标记，并展开修改预览。
3. 只有主动选择 **分叉并重发**，再点击 **分支并发送**，才会另建会话并跳过去，原会话留在列表里。

内容为空时提示无法提交；覆盖模式下文字没改时也不提交。消息已被压缩后，对话框会说明无法再原地改写，不会自动切换到分叉模式；前面没有任何历史时，也提供不了分叉。

## 两种模式的实现

- 浏览器部分把按钮挂进气泡自己的操作行，复用 Copy 按钮的样式；找不到那一行时不显示按钮。
- 覆盖模式在 Host 上追加一条带 `surfaceOp: { op: 'replace' }` 的 `user/message`，只作用于那一个节点，并且走 `agent.runMaintenance()`，不会和正在跑的轮次抢写。这和上下文压缩、工具结果裁剪用的是同一套核心机制，所以卸载插件后会话仍然可读。
- 只有主动选择分叉模式，浏览器才调用 `sessions.fork({ atSeq })` 建分叉，再由 Host 在新会话上发一次 followup。
- 浏览器只调用带 owner 认证的 `POST /message-edit/op`，不直接改会话日志。

## 限制

- 覆盖模式要求 Agent 空闲，正在运行的轮次要先停止。
- 消息被压缩后，覆盖模式拒绝执行，不会自动分叉。
- DSH 的聊天只渲染追加的消息。覆盖模式修改模型上下文，保留原气泡和后续消息，通过修改预览展示保存的文字。
- 只有你自己输入的消息（source 类型 `user`）才有这个控件；steering 行、注入的上下文和定时提示词没有。
- 覆盖模式会让 provider 的 prompt 缓存从这条消息起失效。
