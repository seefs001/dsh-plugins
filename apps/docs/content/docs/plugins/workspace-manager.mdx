<PluginFacts slug="workspace-manager" />

列出 DSH 保存的所有工作区，包括没有会话的、目录已在磁盘上删除的。可以移除单条记录，也可以一次清理所有失效记录。磁盘上的文件和会话都不会被删除。

## 安装

<InstallCommand slug="workspace-manager" />

需要默认 Web profile 里的 Workspace 服务。启用后刷新网页，点侧边栏的 **工作区管理**。

## 使用

- 页面列出所有保存的工作区，可以按名称或完整路径搜索。
- 点 **移除** 并确认，这条记录就从原生工作区列表和选择器里消失。目录不需要存在。
- 打开页面时会检查目录，点 **检查目录** 可以重新检查。检查在运行 DSH Host 的电脑上进行，不在浏览器所在的设备上。
- 点 **清理失效记录** 会重新检查全部工作区，列出要移除的路径，确认后逐条移除。它针对全部工作区，不受搜索条件影响。
- 只有路径不存在（ENOENT）或路径本身、父路径不是目录（ENOTDIR）的记录会进入批量清理。权限不足、I/O 错误等情况显示为 **无法检查**，不进入批量清理。

## 数据与安全

磁盘目录和 DSH 的工作区记录相互独立，删除目录不会自动移除记录。插件调用原生的 `workspaces.delete(workspaceId)`：文件、会话日志和正在运行的会话都保留，也不直接编辑 storage 文件。移除工作区后，它的会话仍可以从原生的全部会话和搜索入口打开。

目录检查只是一次快照。断开的外置磁盘或网络挂载也可能显示为不存在，所以插件不会在后台自动移除记录。确认前请核对完整路径。即使确认后才发现挂载恢复了，磁盘内容也没有被删除。

每次清理结束后显示成功数量。中途失败时，已经移除的记录保持移除，后续移除停止并显示错误，解决后可以重试。确认使用浏览器原生确认框，插件不另存状态。

## HTTP

`GET /workspace-manager/check` 返回 `{ checks: [{ workspaceId, path, status, code? }] }`，`status` 为 `directory`、`missing`、`not-directory` 或 `unavailable`。路由走 Host 的常规连接检查，只检查已注册的路径，不接受任意路径，也不执行移除。
