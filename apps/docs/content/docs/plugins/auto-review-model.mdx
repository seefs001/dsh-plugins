<PluginFacts slug="auto-review-model" />

将 Auto review 审查请求（`purpose: "auto-review"`）路由到指定模型与推理强度，支持追加或替换内置审查提示词，并在会话内提供实时审查日志。

<Callout type="warn" title="前置条件">
需要已启用 `@deepseek-ai/dsh-experimental-auto-review` 与 `@deepseek-ai/dsh-storage-domain`。
</Callout>

## 安装

<InstallCommand slug="auto-review-model" />

## 模型与审查提示词

打开 **Plugins → dsh-auto-review-model**：

- **审查模型与推理强度**：选择专用模型，或保持 **跟随会话**。若所选 provider 不可用，自动回退到当前会话模型并记录警告。
- **审查提示词**：
  - **内置（`default`）**：使用 Auto review 原生策略。
  - **追加规则（`append`）**：接在内置规则末尾，保留原有风险分级和 JSON 格式要求。
  - **替换（`replace`）**：整段替换内置策略，可点击 **载入内置提示词** 作为基准。

<Callout type="warn" title="替换模式需保持严格 JSON 输出">
Auto review 要求模型只输出 `{"risk":"low|medium","decision":"allow"}` 或 `{"risk":"medium|high","decision":"deny","reason":"..."}`。格式不合法会导致审查失败并拦截工具调用。
</Callout>

## 会话审查日志

Auto 模式下，输入框左侧显示审查标签与本会话计数。点击打开实时日志面板（SSE 推送），支持：

- 展开每次调用的完整工具参数与判定理由；
- 点击跳转到对话中对应的工具调用（含 `run_code` PTC 父调用）；
- 快捷打开审查设置页或点击 **Clear** 清空本会话记录。

## 存储

设置保存在 profile 的 `cordis.patch.yml`；日志存在本机 Host 的 `auto_review_log` storage domain，每会话最多保留最近 200 条、全局最多保留 300 个会话，工具参数截断至 4000 字符，理由截断至 2000 字符。
