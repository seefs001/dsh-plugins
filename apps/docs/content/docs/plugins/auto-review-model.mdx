<PluginFacts slug="auto-review-model" />

Auto review（`@deepseek-ai/dsh-experimental-auto-review`）默认用会话自己的模型审查工具调用。这个插件把审查请求（`purpose: "auto-review"`）改道到你选的 provider 和模型，也可以追加或替换审查提示词。主对话不受影响。

## 安装

<InstallCommand slug="auto-review-model" />

先在 Plugins 页启用 `@deepseek-ai/dsh-experimental-auto-review`。

## 使用

1. 打开 **Plugins → dsh-auto-review-model**。模型列表就是 Host 的实时模型目录，和输入框的模型选择器相同。
2. 选择模型，按需选择推理强度，点 **Save**。选“Same as session”恢复内置行为。
3. 会话的权限模式是 Auto review 时，输入框工具行会出现 **Review: 模型名** 标签，显示这个会话的审查次数。有审查拒绝或失败时，数字变红，显示为“拒绝数/总数”。配置的 provider 没有加载、审查退回会话模型时，标签变成琥珀色。
4. 点标签打开审查日志：时间、工具、结论和风险、拒绝理由或失败原因；展开后可以看到审查模型、耗时和被审查的参数。标题栏的 **Review settings** 打开插件设置，**Clear** 删除这个会话的记录。

点一条日志会滚动到对应的工具调用并短暂高亮。PTC 里的内层调用可能跳到外层工具卡片。目标不在已加载的历史里时，界面会提示，不会自动加载更早的消息。

## 配置

| 字段 | 含义 |
| --- | --- |
| `provider` | provider 路由 ID。留空沿用会话模型 |
| `model` | 模型 ID，必须和 `provider` 一起设置 |
| `reasoningEffort` | 该模型的推理强度 ID。留空用模型默认值 |
| `promptMode` | `default` 使用内置审查策略；`append` 在内置策略后追加 `prompt`；`replace` 用 `prompt` 替换内置策略 |
| `prompt` | 追加的规则，或替换用的完整策略 |

## 审查提示词

追加（append）更安全：你的规则放在内置策略之后，标题是 `ADDITIONAL USER POLICY`，风险等级和输出格式保持内置。

替换（replace）会把你的文本作为审查者的完整系统提示词。Auto review 仍然严格解析回答，所以提示词必须让审查者只返回一个 JSON 对象，组合限于 `low+allow`、`medium+allow`、`medium+deny`、`high+deny`，只有 deny 时可以带 `reason`。其他输出都算审查失败，工具调用会被拦下。**Load built-in prompt** 会填入最近一次 Auto review 请求里的策略，Host 启动后至少要跑过一次 Auto review 才有内容。

## 数据

每次审查结束后，Host 把一条记录追加到 `auto_review_log` storage domain，每个会话一个 JSON 文档。每个会话保留最近 200 条，最多保留最近 300 个会话。参数截断到 4000 个字符，理由截断到 2000 个字符。参数可能包含敏感值，只保存在这台机器上。

日志里的结论按 Auto review 自己的解析规则得出。在审查者回答前后失败的审查（例如被中止）记为失败。

## 原理

一个前置的 `llm/stream` 监听器匹配 `purpose === "auto-review"`，复制这个冻结的请求，换上配置的路由和系统提示词，再为副本发起新的 `llm.stream()`。副本去掉 `temperature`：Auto review 把它固定为 0，而推理模型不接受采样温度。其他 `llm/stream` 监听器仍然只看到一次改道后的请求。配置的 provider 没有加载时，审查沿用会话模型，并记录一条警告。

## 限制

- 审查者必须返回严格的 JSON（`{"risk":…,"decision":…}`）。能力较弱的模型经常失败，失败的审查会拦下调用（`AUTO_REVIEW_FAILED`）。
- Auto review 是实验功能。它改变 `purpose` 标记或请求结构时，这个插件需要更新。
