---
title: 自动审查模型
description: 为 Auto review 单独设置审查模型、推理强度和提示词。
---

`dsh-auto-review-model` 只重定向 `purpose: "auto-review"` 的审查请求，主对话模型不受影响。**Host + Web**。

<Callout type="warn" title="先启用 Auto review">
需要启用 `@deepseek-ai/dsh-experimental-auto-review`。这个插件只扩展审查配置，不会自行启用实验性审查功能。
</Callout>

## 安装与设置

```bash
dsh plugin --profile web add "github:seefs001/dsh-plugins#main&path:/packages/auto-review-model"
```

1. 打开 **Plugins → dsh-auto-review-model**。
2. 从 Host 实时模型目录中选择模型，可选推理强度。
3. 点击 **Save**。选择 **Same as session** 恢复内置行为。

## Review 标签与审查日志

会话处于 Auto review 权限模式时，输入框工具行会显示 **Review: 模型** 标签和当前会话的审查次数。存在拒绝或失败时，计数以红色显示；配置的 provider 未加载、回退到会话模型时，标签呈琥珀色。悬停可查看 provider、推理强度和提示词模式。

点击标签打开当前会话的日志，可查看时间、工具、风险、判定和拒绝原因或错误。展开记录可查看审查模型、耗时及截断后的工具参数。面板顶部的 **Review settings** 打开插件设置，**Clear** 清除当前会话记录。

点击日志条目可定位审查对应的工具调用，展开、滚动并短暂高亮。PTC 内层调用可能定位到外层工具卡片。目标不在已加载历史中时会显示提示，不会自动加载更早消息。

### 存储与隐私

日志写入 Host 的 `auto_review_log` storage domain，使用 per-record 布局。默认 JSON 后端在 `~/.dsh/storages` 下按会话保存记录，保留每个会话最近 200 条审查，以及最近 300 个有审查记录的会话。

工具参数截断到 4,000 字符，原因截断到 2,000 字符。参数可能包含敏感值，请按本机数据管理，不要直接分享日志。日志反映 Auto review 的解析结果，中止或流结束异常也会记为失败，不是完整审计档案。

## 配置项

| 字段 | 含义 |
| --- | --- |
| `provider` | provider 路由 ID，留空沿用会话模型 |
| `model` | 模型 ID，必须与 `provider` 一起设置或清空 |
| `reasoningEffort` | 推理强度 ID，留空使用该模型默认值 |
| `promptMode` | `default`、`append` 或 `replace` |
| `prompt` | 追加规则或完整的替代审查策略 |

## 审查提示词

- **Default**：保留内置策略。
- **Append**：在内置策略后，以 `ADDITIONAL USER POLICY` 标题追加规则。保留内置风险等级和输出格式，通常优先选这个。
- **Replace**：把你的文本作为审查模型的完整 system prompt。

<Callout type="warn" title="Replace 必须保留严格输出约束">
Auto review 仍然严格解析结果。提示词必须要求只返回一个 JSON 对象，且 `risk` / `decision` 只能是下面列出的组合。无效输出会使审查失败并阻止工具调用。
</Callout>

允许的组合：`low + allow`、`medium + allow`、`medium + deny` 或 `high + deny`。只有拒绝时可以附带可选的 `reason`，例如：

```json
{"risk":"medium","decision":"deny","reason":"该操作需要用户确认"}
```

**Load built-in prompt** 会填入最近一次审查请求里观察到的策略。Host 启动后至少运行一次 Auto review，该按钮才有内容可加载。

## 实现与限制

插件前置监听 `llm/stream`，复制冻结的审查请求，替换模型路由和 system prompt，再调用 `llm.stream()`。其他监听器仍会看到一次重定向后的请求。

- 指定 provider 未加载时，回退到会话模型并记录警告。
- 审查模型必须稳定返回严格 JSON。审查失败会阻止调用，错误为 `AUTO_REVIEW_FAILED`。
- Auto review 是实验性功能。若上游改变 `purpose` 标签或请求结构，插件需要随之更新。
