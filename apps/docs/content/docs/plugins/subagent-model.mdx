---
title: 子代理模型
description: 在子代理输入框右下角显示只读模型名和推理强度，保留主代理原有的模型选择器。
---

`dsh-subagent-model` 为子代理补上输入框右下角的模型标签。字体、行高、主题颜色和紧凑模式沿用内置模型标签的呈现规则；主代理仍使用原来的模型选择器。

- **组成**：Web，仅在 `dsh web` 浏览器界面显示。Host 入口为空，仅用于加载 bundle。
- **配置**：无需配置，不需要额外 API Key、实验 bundle 或其他社区插件。
- **兼容范围**：dsh `>=0.2.2-rc.1 <0.3.0`，Node.js `^22.19.0` 或 `>=24`。
- **内置依赖**：对话界面、模型选择和语言服务。

## 安装

安装到当前 Web 界面使用的 profile，以下以 `web` 为例：

```bash
dsh plugin --profile web add "github:seefs001/dsh-plugins#main&path:/packages/subagent-model"
```

也可以在 **Plugins** 页面粘贴同样的 GitHub 地址。安装、启用会影响该 profile 的所有会话，不只当前对话。

GitHub 安装要求插件已经存在于 `main`。尚未发布的本地改动，请在仓库根目录使用：

```bash
dsh plugin --profile web add link:$PWD/packages/subagent-model
```

插件是原生 JavaScript，没有安装脚本或构建步骤。以插件管理器返回的激活结果为准；若提示需要重启，先重启对应 profile，再检查 Web 页面。

## 怎么使用？

1. 打开子代理本身的会话，而不是仅展开主代理消息中的工具调用摘要。
2. 查看输入框右下角的模型名与推理强度。
3. 悬停标签，查看 provider/model 标识和只读说明。

标签没有下拉箭头，也没有切换模型的点击操作。子代理的模型由主代理指定；插件只展示已有记录，不改变请求路由、提示词或推理设置。

- 普通主代理会话不增加新标签，原来的模型选择器保持不变。
- 长名称会截断；输入框进入紧凑模式时，显示模型图标。
- 中英文跟随界面语言，颜色跟随主题。
- 可以与[快速模式](</docs/plugins/service-tier>)、[模型引用](</docs/plugins/model-reference>)和[记住模型](</docs/plugins/remember-model>)共存，但不依赖它们。

## 模型和推理强度来自哪里？

| 显示项 | 数据来源与回退规则 |
| --- | --- |
| 模型选择 | 当前子代理的 `modelSelection` projection，优先 `next`，其次 `lastUsed` |
| 模型名称 | 按记录中的 provider/model 精确匹配共享模型目录；匹配不到时显示记录中的模型 ID |
| 推理强度 | 优先使用记录中的 effort，目录提供易读名称；没有对应名称时保留 effort ID |
| 未显式记录的推理强度 | 显示模型目录声明的默认值；支持推理但没有声明默认值时显示“提供方默认” |
| 尚无模型记录 | 显示“尚无模型记录”，不借用主代理或全局默认模型 |

<Callout>
未显式记录推理强度时，目录默认值只是与主代理选择器一致的显示回退，不是已确认的 provider 运行结果。没有推理元数据或 effort 记录时，不额外猜测推理强度。
</Callout>

插件只订阅已有投影和共享模型目录，不额外调用模型，不写入模型选择或浏览器偏好，也不新增自定义存储。

## 实现与停用

插件在 `conversation.input.right` 中注册自己的 `subagent-model` 条目，排在快速模式开关之后。它不替换 `conversation.input.model` 或整个输入框，也不会调用子代理不支持的选模接口。

在 **Plugins** 页面停用或移除“子代理模型”即可恢复原界面。已有会话、模型设置和正在执行的子代理不受影响。

## 为什么没有显示？

1. 确认打开的是子代理会话。主代理会话不会增加只读标签。
2. 确认插件安装到当前运行的 profile，并且 bundle 已启用。
3. 确认使用 Web 界面，且内置对话、模型选择、语言服务可用。终端界面没有新增标签。
4. 激活后刷新 Web 页面；若插件管理器提示待重启，先处理该状态。

看到“尚无模型记录”说明子代理投影还没有模型选择，不表示 provider 报错。看到原始 ID 说明目录中没有匹配的易读名称，插件不会因此改用其他模型。

安装成功和插槽注册成功不等于完成视觉验收。检查显示时，应使用真实子代理会话，确认模型名与记录一致、长名称与窄窗口下可读、明暗主题正常，并返回主代理确认原选择器仍可使用。
