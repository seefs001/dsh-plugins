<PluginFacts slug="acp-workbench" />

`dsh-acp-workbench` 把本机 ACP（Agent Client Protocol）CLI 接入 DeepSeek Harness（DSH），同时保留 DSH 原有的输入框、附件、消息时间线、停止按钮和子代理树。外部执行轨迹和人工交互直接嵌入当前对话，不再另开一套聊天输入框。

默认预设 **Cursor**、**Antigravity** 和 **Claude Code**，也可添加其他本机 ACP CLI。不依赖 Paseo daemon 或 Hub。

## 怎么用：两条主线 + 一个工作台

| 入口 | 怎么启动 | 工具与权限归谁 | 适用场景 |
| --- | --- | --- | --- |
| **会话内直接执行** | 在原模型选择器选择 `acp-*` 提供方下的模型 | 外部 CLI 自己的工具、登录态和权限 | 把当前 DSH 会话交给 Cursor / Antigravity / Claude Code 直接跑 |
| **DSH 主导委派** | 保留普通 DSH 模型，调用 `subagent_cursor`、`subagent_antigravity` 或 `subagent_acp_claude_code` | 子任务用外部 CLI，父会话继续用 DSH 工具和 MCP | 由 DSH 编排拆任务、并行运行并用 `send_message` 续聊 |
| **ACP 工作台（侧栏）** | 打开左侧栏 **ACP 工作台** | 管理项目、工作树、终端、脚本、审阅和跨会话活动 | 按项目同时推进多个 Agent、排查连接与集中批审批 |

<Callout type="warn" title="外部 CLI 不受 DSH 工具沙箱限制">
外部 CLI 使用自己的登录账号、计费、工具和文件访问权限。插件只拦截并展示 CLI 实际发来的审批请求，无法保证外部操作都会事先询问。请不要把密钥写进命令行参数。
</Callout>

## 安装与准备

<Steps>
<Step>

### 安装并登录本机 CLI

在终端安装对应 CLI 并完成登录，确保命令可执行：

| 默认提供方 | 默认可执行文件 | 默认参数 |
| --- | --- | --- |
| Cursor（`cursor`） | `cursor-agent`（优先 `~/.local/bin/`，否则取 `PATH`） | `["acp"]` |
| Antigravity（`antigravity`） | `agy` | `["acp"]` |
| Claude Code（`claude-code`） | `claude-agent-acp` | `[]` |

</Step>
<Step>

### 安装插件

<InstallCommand slug="acp-workbench" />

安装包会自动注册 `acp-*` 模型路由以及三个原生子代理工具。

</Step>
<Step>

### 检查能力并勾选模型

打开左侧栏 **ACP 工作台 → 提供方**：

1. 核对或新增提供方的名称、可执行文件和参数（已保存提供方的 ID 不可修改）。
2. 填写一个项目的绝对工作目录。
3. 点击 **检查能力**：只运行 ACP `initialize`，展示协议版本、登录方式与能力标签，不发送任务。
4. 点击 **刷新模型**：新建一个空 ACP 会话读取候选模型并缓存描述、上下文与思考强度信息，不发送任务，也不会自动改动主模型选择器。
5. 勾选需要出现在主模型选择器中的模型，点击 **保存模型选择**。

</Step>
</Steps>

## 在当前会话直接执行

选好 `acp-*` 模型后，继续用 DSH 原生输入框提问、传附件或点击停止即可。

<Tab value="模型与控制">

### 模型、思考强度与 CLI 设置

- **模型选择**：主模型选择器只列出你勾选保存的模型以及 `CLI default`（沿用 CLI 当前使用的模型，不预设模型名或上下文大小）。选择具体模型后，插件会在发送消息前通知 CLI 切换模型；若切换被拒绝，本次不会发送任务。
- **思考强度**：支持思考强度的模型可直接使用原选择器内的强度控件。标准 ACP 走模型公布的 `thought_level`；Cursor 完整变体（如 `gemini-4-hydrogen[reasoning_effort=high]`）则映射到同家族、其他参数一致的已公布变体，不会自行拼接未公布的模型 ID。`CLI default` 不提供独立强度覆盖。
- **CLI 设置浮层**：在原模型菜单点击 **CLI 设置**，输入框上方会弹出浮动设置面板（普通 DSH 模型不出现该菜单项）：
  - 实时修改该 CLI 公布的模式与配置项；
  - 从面板里的 **工作区工具** 快捷打开原生文件、Git 改动或新建终端面板；
  - 查看连接状态、仅连接不发消息，或在 **CLI 命令** 区域手动触发 CLI 命令；
  - 连接或修改配置期间，你在输入框提交的消息会在原生队列中排队等待。

### 在输入框使用 `/cli:` 命令

当连接的 Agent 处于空闲状态时，在输入框行首输入 `/` 并继续输入命令片段筛选，即可在 CLI 分组看到 `/cli:<名称>`、说明与参数提示。选中后只会在输入框插入命令标签；补齐参数并发送，CLI 才会收到 `/名称 参数`，不会误触发 DSH 同名斜杠命令。

> 草稿重载、CLI 重连或命令表更新后，请删掉旧命令标签再从菜单重选。命令只接受文本，不支持附件。

### 新建外部上下文

在异常恢复区点击 **新建外部上下文** 会退役当前外部绑定，下一条消息将新建一个远端会话。原有的 DSH 消息和旧执行轨迹都会保留，不删除磁盘文件或 CLI 历史。

</Tab>
<Tab value="执行轨迹与卡片">

### 可折叠的执行轨迹与最终回复

每轮回答旁都有一行默认折叠的 **执行轨迹**（显示状态、工具调用次数和改动文件数），点击整行展开或收起（展开后底部也提供 **收起轨迹** 按钮）。展开后按时间顺序呈现该轮的外部事件：

同时，ACP 轮次执行完成后，最终回复末尾会显示 **收起结果** 按钮；点击即可把整段长回复折叠为一行带行数与首行摘要的提示条（折叠状态记在当前浏览器，页面内查找命中时会自动展开）。在 **项目 → 项目审阅** 中，较长的回复摘录同样支持折叠与 **展开全文**。

- **概览 / 逐条视图**：默认 **概览** 会把连续完成的读取、搜索与网页查询合并为一条查阅摘要（展开可看每次调用与行号，支持点击文件路径预览）；正在执行、失败、涉及审批、命令和编辑仍单列。切到 **逐条** 后，当前浏览器会记住偏好。
- **写入文件与多文件补丁**：Claude 的 **写入文件** 与 **编辑文件** 分开显示。展开写入调用可切换 **请求写入的正文** 与 **报告的补丁**；多文件编辑支持按文件过滤或切回 **全部报告片段**，并标明补丁来源（启动时的预览 / 审批请求 / 更新 / 完成 / 失败）。
- **命令输出（只读终端卡）**：支持流式分片的 CLI 会在运行中实时更新输出，保留末尾 32 Ki 字符并显示退出码或信号；若工具完成时另报了汇总结果，可在 **终端回报** 与 **工具另报的输出** 之间切换。卡片只读，不能在里面输入或重跑。
- **MCP 工具**：直接标明「服务 / 工具」，区分调用参数、展示说明、混合媒体块以及按行展开的结构化记录列表。
- **网页工具**：区分 **网页搜索**（查询词、域名限制、按序来源）、**抓取网页**（目标 URL、提取要求与返回文本）和 **页内查找**（查找词）。CLI 未传回正文时明确提示，展开卡片不会发起联网请求。
- **本轮 CLI 子任务**：当 Claude ACP 报告父调用 ID 时，轨迹提供只读的 **查看子任务** 入口，可单独查看该子任务发起的调用、计划、进展与审批回执，遇到嵌套任务可继续下钻，也可以切回 **完整轨迹**。这个视图不会新建第二个 DSH 会话。
- **计划与上下文压缩**：计划卡片区分任务清单与方案 Markdown 原文（含可选当前文件跳转）；**CLI 上下文压缩** 卡片显示摘要、失败原因或压缩前后 token 数（如 CLI 提供）。

</Tab>
<Tab value="接续与复制 CLI 历史">

### 从 CLI 旧会话继续

在首次发送消息前，从模型菜单打开 **CLI 设置 → 接续 CLI 会话**：

1. 插件按当前 DSH 会话的工作目录调用 `session/list` 列出可接续的历史记录（无需手动填路径）。
2. 点击 **在这里接续** 只会连接旧上下文，不发送提示词；随后发送的第一条消息会直接接在 CLI 原上下文之后，不会把本页之前的 DSH 对话打包附带过去。
3. 若该 CLI 会话已绑定另一个 DSH 会话，按钮会直接带你打开原会话。CLI 回放的前文可在卡片按需展开，不会插成 DSH 新消息。

### 保留原对话，从副本继续

想保留原对话并尝试另一条路线时：

1. 在**同一工作目录**打开一个新的、尚未绑定 CLI 的 DSH 会话，并在模型选择器选中同一提供方。
2. 打开 **CLI 设置 → 接续 CLI 会话**，在原记录旁点击 **从副本继续**（仅当 CLI 同时支持列出、`session/fork` 与恢复能力时显示）。
3. 插件会基于 CLI 已保存的最新历史复制出带独立 ID 的新外部上下文，不自动发提示词，也不会改动原会话或新建 worktree。

</Tab>
<Tab value="审批、提问与用量">

### 权限、表单与计划审批

- **审批卡片**：工具权限请求、Cursor 提问与计划审批都会出现在输入框上方。权限卡标明调用 ID、CLI 目录以及各选项是一次性允许还是可能影响后续请求；如果 CLI 没有随请求附带预览参数，可展开 **查看最初的工具调用** 核对启动时的报告。
- **自动授权边界**：只有当所属 DSH 会话显式使用完全访问预设（`danger-full-access` 且 `approval: never`），且 CLI 提供了 `allow_once` 选项时，插件才会自动选择一次允许；持久授权、提问与计划审批始终需要人工决定。
- **CLI 表单提问**：Claude Code 的 `AskUserQuestion`（`elicitation/create`）以原生表单呈现单选、多选、补充文本与只读示例。仅点击 **提交回答** 时发送已填字段；**不回答** 与取消分别通知 CLI。请勿在表单里填写密码或令牌。

### 提醒、上下文占用与用量

- **CLI 会话提醒**：轮次内收到的提醒留在当轮执行轨迹中；连接时或轮次间收到的提醒（如 MCP 启动失败、模型临时回退）会以纯文本显示在输入框下方的 **CLI 会话提醒**（仅列当前连接最近 8 条）。提醒不是审批，标为错误也不等于本轮失败。
- **上下文与累计用量**：输入框下方的 **CLI 上下文 · 最近报告** 显示当前连接上次实报的窗口占用、模型与会话累计费用；每轮执行轨迹末尾则保留该轮结束时 CLI 返回的 **CLI 会话累计 token**。未报告的字段保持未知，不按 `0` 填充，也不代表账号剩余额度。

</Tab>
</Tabs>

## 由 DSH 主模型委派子任务

如果你想保留普通 DSH 模型来统筹任务，把具体代码修改或调研交给外部 CLI，可以直接使用委派模式：

- 插件挂载了 `subagent_cursor`、`subagent_antigravity` 与 `subagent_acp_claude_code` 三个工具。如果会话的工具选择器没有默认勾选它们，请先在工具选择器启用。
- `subagent_acp_claude_code` 走 ACP 协议，与官方非 ACP 工具 `subagent_claude_code` 互不冲突；此前单独勾选过旧 ACP 工具名的预设请改选新工具名。
- 每次委派都会创建真实的、可续聊的 DSH 子会话：可用 `send_message` 继续对话，也可在原生子代理树查看与停止。
- 需要人工回应或正在运行中的子任务会优先显示在父会话输入框下方，不用展开子代理轨迹就能直接审批；已安静的子任务折叠在 **其他子任务** 中。

## 按项目协同工作（ACP 工作台 → 项目）

打开侧栏 **ACP 工作台 → 项目**，你可以把 DSH 的工作区、工作树、终端、脚本、Git 审阅和定时任务串在同一处使用。

### 1. 创建、共享与恢复工作树

- **新建 Agent**：选择 DSH 工作区（或 **添加目录**），选定引擎、模型、思考强度与隔离方式（**使用项目目录** 或 **独立工作树**）。独立工作树需要启用 DSH worktree 能力，支持指定新分支和起始 ref；常用组合可保存为跨项目复用的 **启动配置**。创建只开新会话，不自动发消息。
- **共享同一份工作树**：展开某个托管工作树会话的 **工作目录 → 在这里新建 Agent**，可再开一位使用不同或相同引擎的 Agent 直接编辑同一份代码。每位参与者保持独立的 DSH 会话、CLI 上下文、审批与停止按钮；在项目页和聊天中都可以 **切换同工作树 Agent**。
- **归档与工作树恢复**：归档前可确认是否有未提交改动或其他会话仍在使用。恢复已归档会话后，如果目录已被 DSH 回收，可以在 **工作目录** 点击 **重建缺失的工作树**（优先检出原分支；原分支已不存在时从起点提交重建）。已被占用的路径不会覆盖，也不会悄悄退回源项目根目录运行 ACP。

> Git 忽略规则、`skip-worktree` 或 `assume-unchanged` 隐藏的文件不会阻止 DSH 回收工作树。重要未跟踪产物请在归档前备份，或在 DSH 设置中开启归档保留。

### 2. 查找会话、文件、终端与项目脚本

| 会话行功能 | 做什么 | 关键边界 |
| --- | --- | --- |
| **查找会话与批量整理** | 按名称、项目、引擎、目录或 DSH 会话 ID 在 **当前项目** / **全部项目** 搜索，支持 **只看置顶**、**已归档** 与 **批量归档 / 恢复** | 搜索不查聊天正文；批量归档会跳过正在运行、等待回应或带工作树记录的会话 |
| **查找文件** | 切分 **按名称查找** 与 **浏览目录** 两种模式，基于该会话生效的工作目录搜索或逐层查看，可预览并在文件侧栏打开 | 按名称搜索排除隐藏与 Git 忽略项；浏览目录不显示隐藏项但列出未隐藏的构建产物等忽略项 |
| **会话终端** | 实时列出 DSH 为该会话保留的用户与 Agent 终端，点击 **打开终端** 直接聚焦或绑定原生终端标签 | 不同会话即使共享工作树也不混列；列表仅观测，不自动接管终端或发送输入 |
| **项目脚本** | 读取该会话生效目录的 `paseo.json` `scripts`，确认后在沙箱终端中运行或停止，查看最近一次退出码与输出（最多 8 KiB） | 读取 `$PASEO_PORT` 且未设固定端口的服务支持 **带回环端口启动**（`HOST=127.0.0.1`）与按需 TCP **监测端口**（仅检查端口连通，非 HTTP 健康检查） |

### 3. 项目审阅、Git 提交对比与定时任务

- **项目审阅**：在项目顶部汇总等待回应的请求（含子代理）以及已结束的 ACP 轮次（**待审阅** / **全部结果**）。你可以阅读回复摘录、展开 **本轮轨迹**、点击调用位置跳回文件，或点击 **标为已审阅**（已读状态不影响审批，打开审阅也不会自动放行请求）。
- **工作树改动与旧版本核对**：
  - 在结果卡或会话行打开 **工作树改动**（需启用 DSH Forge），可对比工作树与 HEAD、已暂存、未暂存、基线分支，或切换到 **分支上的提交** 选择单次提交及连续第一父提交范围。
  - 点击补丁**右侧行号**查看新侧文件（已暂存看 Git 索引，提交范围看结束提交，工作树可跳至文件侧栏）；点击**左侧行号**直接查看补丁里的旧行，必要时点击 **读取完整旧版本** 按对比范围读取 Git 索引、HEAD 或起始提交第一父提交。
- **定时任务**：在项目页点击 **定时任务**，支持创建 **已有会话（定时唤回）**、**首次新建后复用** 或 **每次新建** 三种目标，支持延时、固定间隔、每天定时与带时区的 5 字段 Cron，并可立即投递、暂停/恢复、查看投递历史与删除。**已投递不等于 Agent 已完成**。

## 活动收件箱与诊断

侧栏 **ACP 工作台 → 活动** 把所有 ACP 绑定按优先级分成五组：

1. **等你回应**：存在待处理权限、提问或计划审批的绑定。
2. **进行中**：正在连接、准备或运行中的绑定。
3. **需查看**：连接出错、上轮失败或因 Host 重启中断的绑定。
4. **最近活动**：当前空闲或已完成轮次的绑定。
5. **历史**：已归档或已退役（新建外部上下文后保留）的记录。

点击记录可进入详情页进行重命名、连接/重连/断开、停止本轮、归档/恢复，以及分页检查 **时间线** 与 **原始事件**。

此外，插件仍保留模型工具 `acp_workbench` 作为高级兼容与诊断入口，支持操作旧式独立记录；**绑定到 DSH 会话的记录对其只读（`get` / `events`）**，不能用它发消息、断开、归档或替代原生子代理委派。

## 上下文交接、附件与使用边界

- **会话绑定规则**：一个 DSH 会话与一个 ACP 提供方对应一个外部上下文；同一 DSH 会话切换不同 ACP 提供方时各自保留上下文；DSH 会话分叉会建立新的远端上下文，不复用父会话远端 ID。
- **交接与限制**：首次使用或中途在其他模型上产生过对话后切回 ACP 时，插件只把尚未交接的历史文本包裹为上下文块发给 CLI（不把历史工具输出当作系统指令），单次上限 **200,000 字符**，超限明确报错。
- **恢复与防重发**：断线重连或冷子任务续聊优先使用 `session/resume`，仅在 CLI 明确返回 `-32601` 且支持 `loadSession` 时回退 `session/load`。Host 重启后中断的任务不会自动重发，需人工重新下达指令。
- **附件处理**：CLI 宣布支持图片时转发当前输入图片；返回图片存入 DSH 附件系统（格式不支持或损坏时在回复中给出指向原始事件的提示，不中断整轮）；普通文件通过本机只读路径或 resource link 交接；历史附件仅保留文本说明。
- **不替代的 DSH 功能**：ACP 路由不处理标题生成、DSH 压缩等辅助调用；不透传 DSH MCP，不宣告 ACP 客户端 `filesystem`/`terminal` 能力；不新增远程中继、移动客户端、语音或另一套 IDE。
