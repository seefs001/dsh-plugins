<PluginFacts slug="web-access" />

在 Plugins 页为每个搜索工具选一个本地的 Responses 模型和搜索类型。工具调用该模型的托管搜索，返回带引用来源的回答。

| 工具 | 托管搜索类型 | 模型可以传的参数 |
| --- | --- | --- |
| `grok_search` | `web_search`、`x_search` 或两者 | 域名（网页）、X 账号和日期（X） |
| `openai_search` | `web_search` | 允许的域名、上下文大小、位置 |

分成两个工具，是因为 xAI 和 OpenAI 的托管搜索参数不同。每个工具的 schema 只列出你启用的搜索类型对应的选项。

## 配置

打开 **Plugins → dsh-web-access**，为每个工具设置：

- **Enabled**：关闭后移除该工具。
- **Model**：`llm-pi-ai` 中任意 `openai-responses` provider 的模型。端点（`baseURL`）、key（`apiKeyEnv`）和额外的 `headers` 都取自这个 provider，不需要再填一遍。
- **Search type**：Grok 可以用网页、X 或两者，OpenAI 只用网页。

保存后插件重启并重新注册工具。工具只在 provider 路由存在且 key 能解析时提供给模型，页面上显示 **Ready** 或不可用的原因。readiness 检查不会探测上游是否真的支持搜索，HTTP 出错后也不会自动换路。

同样的设置在 `cordis.patch.yml` 中是：

```yaml
- id: web-access
  config:
    timeoutMs: 120000
    grok:
      enabled: true
      provider: responses
      model: grok-4.7-build-fast
      tools: [web_search, x_search]
    openai:
      enabled: true
      provider: responses
      model: gpt-6.1-sol
      tools: [web_search]
```

## 与内置 web_search 的关系

每个模型步骤里，只要有可用的自定义网页搜索，这个 Agent 的内置 `web_search` 就会被隐藏。关闭所有自定义网页搜索、它们的路由或 key 失效、或卸载插件后，限制解除，内置工具恢复正常。只开 X 搜索的 Grok 不会替换网页搜索。`web_fetch` 和内置的搜索 provider 不变。

## 结果

模型收到回答文本和最多 10 个来源。来源取自回答的引用（`url_citation` 注解、响应里的 `citations`，或回答中的 Markdown 链接）；只有回答没有引用时，才使用原始的搜索调用结果。

对话里沿用原生的搜索行：精简的 Grok/OpenAI 标题、查询、搜索渠道和来源数。展开可以读排版后的回答和来源链接。运行中、已停止和失败的调用保留原生状态。Inspect 打开的仍是原始工具调用。

## 可选参数

只有 `query` 必填。所有可选字段都可以省略或传 `null`，包括位置的每个子字段，这样严格模式的 Responses 客户端不必编造日期或位置。只搜网页的 Grok 调用把 X 过滤条件设为 `null`；不需要本地化的 OpenAI 搜索把 `user_location` 设为 `null`。空字符串不能代替 `null`，矛盾或格式错误的过滤条件仍会报错。

## 限制

- 网关是否转发托管的 `web_search` / `x_search` 取决于网关和上游账户。不支持时，返回的是端点的 HTTP 错误。
- `allowed_x_handles` / `excluded_x_handles` 按 xAI 文档中的 `x_search` 字段传递，网关可能忽略它们。
