<PluginFacts slug="web-access" />

注册 `grok_search`（网页搜索与 X/Twitter 帖子搜索）和 `openai_search` 工具。两个工具直接调用你在 `llm-pi-ai` 里配好的 `openai-responses` provider 地址、Headers 与密钥，不需要在插件里重新填写接口地址或 API Key。

<Callout type="info" title="前置要求">
profile 中 `llm-pi-ai` 需至少配置一个 `api: openai-responses` 的 provider，并且其 `apiKeyEnv` 已经在 DSH credentials 或 Host 环境变量中就绪。
</Callout>

<InstallCommand slug="web-access" />

## 配置步骤

<Steps>
<Step>

### 选择 provider 与模型

打开 **Plugins → dsh-web-access**，分别为 **Grok** 与 **OpenAI** 选择对应的 `openai-responses` provider 和模型名称。

</Step>
<Step>

### 选择托管子工具

Grok 后端可独立勾选开启 `web_search` 与 `x_search`；未勾选的子工具及其过滤参数不会出现在 `grok_search` 的参数 Schema 中。点击 **保存** 即生效。

</Step>
</Steps>

## 工具参数与行为

| 工具 | 支持参数 |
| --- | --- |
| `grok_search` | `query`、`sources`（`["web"]` / `["x"]`）、`allowed_domains` / `excluded_domains`（最多 5 个）、`allowed_x_handles` / `excluded_x_handles`（最多 10 个）、`from_date` / `to_date`（`YYYY-MM-DD`） |
| `openai_search` | `query`、`allowed_domains`（最多 100 个）、`search_context_size`（`low` / `medium` / `high`）、`user_location`（`country` / `city` / `region` / `timezone`） |

- **自动屏蔽重复搜索**：只要某会话中至少有一个托管 `web_search` 工具配置就绪并可见，插件会自动在该会话中隐藏 DSH 内置的 `web_search`（不影响 `web_fetch`），避免模型在两个搜索工具间犹豫。
- **密钥与边界**：插件不保存 API Key，只保存 provider、模型和启用的子工具列表到 `cordis.patch.yml`；搜索提示词与结果会发送给所选 provider，错误信息会自动脱敏密钥。
