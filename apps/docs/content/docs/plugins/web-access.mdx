<PluginFacts slug="web-access" />

注册 `grok_search`（网页与 X/Twitter 搜索）和 `openai_search` 工具，直接复用 `llm-pi-ai` 中已有的 `openai-responses` provider 地址、Headers 与密钥。

<Callout type="info" title="前置要求">
profile 中 `llm-pi-ai` 需至少配置一个 `api: openai-responses` 的 provider，且对应 `apiKeyEnv` 已在 DSH 凭据或环境变量中就绪。
</Callout>

## 安装

<InstallCommand slug="web-access" />

## 配置

<Steps>
<Step>

### 选择 provider 与模型

在 **Plugins** 页面打开 **dsh-web-access**，分别为 **Grok** 与 **OpenAI** 选择 `openai-responses` provider 和模型。

</Step>
<Step>

### 选择搜索范围

Grok 可单独开启 `web_search` 与 `x_search`；未启用的子工具及其过滤参数不会出现在工具参数 Schema 中。点击 **保存** 即生效。

</Step>
</Steps>

## 工具参数

| 工具 | 参数 |
| --- | --- |
| `grok_search` | `query`、`sources`（`["web"]` / `["x"]`）、`allowed_domains` / `excluded_domains`（最多 5 个）、`allowed_x_handles` / `excluded_x_handles`（最多 10 个）、`from_date` / `to_date`（`YYYY-MM-DD`） |
| `openai_search` | `query`、`allowed_domains`（最多 100 个）、`search_context_size`（`low` / `medium` / `high`）、`user_location`（`country` / `city` / `region` / `timezone`） |

会话中只要有任一托管 `web_search` 就绪，插件会自动隐藏内置 `web_search`（不影响 `web_fetch`）。插件仅将 provider、模型与子工具配置写入 `cordis.patch.yml`，不存储 API Key。
