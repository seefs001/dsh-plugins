---
title: 压缩状态
description: 在输入框上方显示上下文压缩状态和已等待时间，不必展开过程详情。
---

`dsh-compaction-status` 在上下文压缩期间显示一行 **正在压缩上下文** 和已等待时间。提示位于输入框上方，与原生任务栏同宽、居中。它不使用通栏卡片或第二行说明，悬停时可查看解释。

- **组成**：Host + Web，仅在 `dsh web` 浏览器界面显示。
- **配置**：无需配置，不需要额外 API Key。
- **兼容范围**：dsh `>=0.2.2-rc.1 <0.3.0`，Node.js `^22.19.0` 或 `>=24`。

## 安装

安装到当前 Web 界面使用的 profile，以下以 `web` 为例：

```bash
dsh plugin --profile web add "github:seefs001/dsh-plugins#main&path:/packages/compaction-status"
```

也可以在 **Plugins** 页面粘贴同样的 GitHub 地址。安装、启用会影响该 profile 的所有会话，不只当前对话。

GitHub 安装要求插件已存在于 `main`。尚未发布的本地改动，请在仓库根目录使用：

```bash
dsh plugin --profile web add link:$PWD/packages/compaction-status
```

开启 `patchReload: live` 时，安装后无需重启 dsh。若浏览器仍显示旧版样式，刷新页面加载新的 Client bundle。

## 显示什么？

自动压缩和手动执行 `/compact` 都会显示提示，无需打开折叠的过程详情。正常状态下没有常驻占位。

- 左侧是小转圈和「正在压缩上下文」。
- 右侧是「已等待 0:34」这样的计时，格式为分钟和秒。
- 压缩结束后收起，包括失败的情况；失败原因继续由 dsh 原有界面报告。
- 切换会话时跟随当前显示的会话，不混用其他会话的计时。
- 中英文跟随界面语言，颜色跟随主题；系统启用减少动态效果时，转圈停止动画。

计时从本次压缩的原始开始时间计算。它不是完成百分比，也不是剩余时间预估。浏览器刷新或重连到同一段仍在运行的 Host 压缩过程时，计时不会重新从零开始。

<Callout>
插件只让等待过程可见，不会加快摘要生成，也不修改压缩阈值、摘要模型或历史摘要记录。用 `/compact` 验证显示会执行真实压缩，可能产生模型请求并改变当前上下文。
</Callout>

## 状态与数据

Host 从原生 `compaction/start`、`compaction/end` 会话事件计算 `dsh-compaction-status` projection，Web 通过当前会话的 `useProjection` 订阅。

- 同一次压缩的结束事件会清除提示，无论成功还是失败。
- 自动压缩所属的回合结束时，也会清除未结束的提示。
- 恢复或派生会话时，`session/end-seed` 会清除继承的未结束状态，避免历史压缩被误显示为仍在运行。
- 插件不另存自定义会话记录或浏览器偏好；原生 projection 缓存仍由 Host 管理。
- 客户端只用本地时钟更新计时，不轮询会话事件，不增加模型调用。

停用插件只移除提示，不改变正在执行的压缩。

## 为什么没有显示？

1. 确认当前会话确实正在压缩。普通推理、工具执行和空闲期间不会显示。
2. 确认安装到当前运行的 profile，并在 **Plugins** 页启用压缩状态 bundle。
3. 确认正在使用 Web 界面。终端界面没有新增提示。
4. 若刚更新插件，刷新 Web 页面；未开启 `patchReload: live` 时，还需重启对应 profile 的 dsh。

样式复核应在真实压缩期间进行：查看提示是否与任务栏对齐，在窄窗口和明暗主题下是否可读，并确认结束后收起。插件安装成功或插槽注册成功，不能替代实际显示检查。
