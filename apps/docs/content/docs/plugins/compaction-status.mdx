<PluginFacts slug="compaction-status" />

自动压缩或手动 `/compact` 期间，输入框上方显示一行“正在压缩上下文”和已等待时间，例如 **已等待 0:34**。这一行和原生任务栏同宽、居中，在折叠的过程详情之外，往上翻阅旧消息时也一直可见。

## 安装

<InstallCommand slug="compaction-status" />

没有插件设置，也不需要 API key。插件只显示状态，压缩本身仍由 DSH 原有的流程负责。

## 显示规则

- 计时从原始的 `compaction/start` 时间开始，按分秒显示。它是已经过去的时间，不是进度或剩余时间。
- 刷新页面或重连到同一个仍在运行的 Host 时，起始时间不变。恢复或分叉会话时，继承来的未完成状态在 `session/end-seed` 处清除。
- 对应的 `compaction/end` 出现后状态消失，成功和失败都一样。外层的 `turn/end` 也会清掉未完成的自动压缩。原生的错误提示不变。
- 状态跟随当前显示的会话，切换会话不会串计时。
- 中英文跟随界面语言，颜色跟随主题。系统开启减少动态效果时，加载动画停止。
- 悬停可以看到说明文字。

插件不改压缩阈值、摘要模型、模型调用或历史摘要，也不能让摘要变快。用 `/compact` 测试指示器时，压缩是真实执行的，可能产生模型请求。

## 数据与原理

Host 从持久的 `compaction/start` 和 `compaction/end` 事件派生出 `dsh-compaction-status` 会话 projection，不另存会话记录或浏览器偏好。

Web 部分通过会话范围内 dock 的 `useProjection` 读取它，在 `conversation.input.dock` 注册一个排在任务栏之前的条目。只有本地时钟每秒跳动一次，不轮询会话事件，也不发起模型请求。宽度沿用原生任务栏的 `--dsh-composer-*` 布局变量，不改 Host 的任务、目标、队列或输入框样式。

停用 bundle 会移除 projection 和这一行，不影响压缩流程。

## 排查

1. 确认 bundle 已在正在使用的 profile 里启用。
2. 只有压缩真正在进行时才显示，平时看不到是正常的。
3. 切到别的会话后不显示上一个会话的状态。
4. 刚更新插件时刷新 Web 页面；Plugin Manager 返回 `restart-required` 时先重启。
