`dsh-message-actions` 在已完成回复的点赞点踩旁加入 **Wait, what?**。点击一次，弹窗就会显示缓存，或自动开始独立生成。不需要再发 `/wait-what`，原回复与后续主对话上下文保持不变。

只提供固定的 Wait, what? 解释功能，不支持自定义模板或提示词编辑。需要 DSH rc.2 或更新版本及 Web 界面。

## 安装

```bash
dsh plugin --profile web add link:$PWD/packages/message-actions
```

更新 Host 代码后按安装器提示重启 DSH，再刷新页面。

## 一键解释

1. 点击回复底部的 **Wait, what?**。
2. 有缓存立即显示，没有则自动生成。可停止、复制、关闭，或点击 **重新生成** 绕过缓存。
3. 想更换模型时，打开 **模型设置**，选择后点击 **保存并解释**。

解释正文支持 Markdown/GFM，标题、列表、引用、代码块、表格和任务列表会直接排版，流式生成时同步渲染。复制和缓存保留原始 Markdown。原始 HTML 不会执行；图片显示为链接，不自动加载外部资源。

固定提示词改编自用户本地的 `wait-what` skill：补上必要的前提与联系，使用简单的技术语言重新讲清楚，而不是单纯缩短回复。默认跟随原回复语言，英文遵循 ASD-STE100，其他语言采用相同的简明表达原则。

## 指定模型

在插件页面的 **Wait, what? 专用模型** 中设置，也可从解释弹窗的 **模型设置** 进入。

- 默认 **沿用每条原回复的模型**，包括那条回复对应请求的推理强度。
- 可指定 DSH 已配置的模型，只用于本插件，不改变主对话模型。
- 所选模型支持时，可选择推理强度；留在 **模型默认** 时使用该模型默认值。
- 插件页面的 **保存模型** 影响下一次解释；弹窗的 **保存并解释** 会按新设置读取缓存或生成。
- 设置通过 config editor 保存到当前 profile，所有会话共用，刷新和重启后保留。指定的 provider 不可用时明确报错，不静默改用另一模型。
- 保存失败保留草稿并显示错误。保存期间禁止重复提交，弹窗暂时不能关闭或发起另一生成。

## 独立上下文

调用只带所选回复与它之前最近一条用户消息的文本，不带完整历史、主 Agent 系统提示词、其他技能或工具，不执行文件读取。未提供项目术语表时沿用原文术语，不声称读过术语表。如果提供的两条消息缺少关键前提，解释可能不完整。

<Callout>
一键按钮直接调用模型，不向主对话追加用户消息、工具调用或二次解释。若通过 Agent 的 `message_actions` 工具操作，则仍遵守正常的工具日志规则。
</Callout>

## 缓存与隐私

- 结果保存在 Host 的 `message_actions` storage domain，刷新和重启后仍可读取，多个浏览器共用。
- 缓存键包含会话、消息、原文、上一条用户消息、解析后的模型参数和固定提示词。切换模型或推理强度后分别匹配，切回来可复用仍保留的旧结果。
- 最多保留最近 200 份完整结果。相同键重新生成会替换旧结果，没有自动过期时间。
- 失败、中断、空输出或达到输出限制时，不把不完整文本存为缓存，已有结果保留。
- 旧版本模板不再读取或暴露，也不主动删除已有磁盘记录；旧缓存只有完全匹配固定解释时才会复用。

<Callout>
提示词和结果明文存储在 Host。生成时所选文本发给指定模型服务，未指定时发给原回复的模型服务，不发送整个对话、附件或思考过程。浏览器操作只对 Host owner 开放。
</Callout>
