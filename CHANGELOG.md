# Changelog

## Unreleased

- `dsh-title-model` 0.1.0: choose a separate model for native first-prompt or conversation-following session titles on the bundle’s Plugins page, or through `title_model`. Writes only the native generator’s provider/model configuration, preserving the title strategy and conversation model. Saved choices persist after disabling this settings plugin. Not yet exercised in a running DSH.

- `dsh-pi-tools`: save Host-wide tool defaults per preset as differences from the configured defaults, reset them from the picker, and freeze saved defaults into a session when its first step begins. **Refresh MCP** restarts bridged servers and reloads their tools, reporting server status and tool counts.
- `dsh-pi-tools`: use Pi 1.5.0's complete system-prompt builder and original MCP-server section, including Pi's preamble, documentation links and working directory. Remove plugin-added system-prompt paragraphs; codemode string guidance remains in error feedback. Mark the older prompt comparison report as historical. DSH still owns runtime context, permissions and subagent execution.
- `dsh-roles`: dedicated sidebar manager with retained in-page drafts, prompt/skills/model-preview tabs, emoji picker, field validation and a fixed save bar. Roles can reference local skills by name through the native skill catalog, including a chosen project's skills, without copying files or changing which other skills a session can use.
- `dsh-paseo-hub`: organization API console independent of daemon enrollment: scoped key stored in Host credentials, read-access checks, searchable/paged triggers, YAML validation and confirmed installation, manual dispatch with stable delivery keys, project/daemon/provider resource lookup, and complete legacy configuration bundles. Shared `paseo_hub` and `paseo_hub_write` tools; agent writes default off and can only be enabled by the owner. API outcomes join the local activity journal. New owner-only `POST /paseo-hub/api` route.
- `dsh-paseo-hub`: redesigned page following the Plugin Manager layout and host primitives. Tabs for Overview (clickable run counts, connection, latest runs and activity), Runs (search, status filters with counts, pagination, expandable details, stop, open, copy, archive, restore, remove), Activity (a persistent journal of connection changes, Hub requests, run outcomes and page actions, with source, problem and per-run filters, search, pagination and clear), and Setup (modes, a copyable trigger snippet, plugin settings). Run records now keep outcome, turn count, last activity and last error. New owner-only routes `GET /paseo-hub/runs` and `GET /paseo-hub/events`; `/paseo-hub/state` returns counts and the latest five runs instead of 20. Destructive actions confirm in a modal dialog.
- `dsh-paseo-hub` 0.1.0: connects the Host to Paseo Hub as a daemon. The sidebar **Paseo Hub** page signs in through Hub's CLI device login (or an organization API key), enrolls with `hub.execute`, and keeps the daemon WebSocket open with backoff. Hub sees one provider, `dsh`: models are `<DSH provider>/<model>`, thinking options are reasoning efforts, and modes are permission presets. Each Hub agent is a DSH session with Hub's MCP server mounted on its own Agent, Hub's preapproved tools allowed in that session only, and Hub's environment passed to its bash commands. Disconnect revokes the daemon on Hub. Needs a Hub that accepts `dsh` for unattended triggers. Verified end to end against a local Hub.
- `dsh-pi-tools`: MCP tools another plugin mounts on one Agent's own scope, such as Paseo Hub's per-run `reply` and `finish_execution`, now reach that Agent as direct tools. A saved Pi tool selection no longer hides them. Global MCP servers are unchanged.
- `dsh-roles` 0.1.0: role manager. A role is a detailed prompt plus its own skills; pick one per session from a **Role** row in the composer's model menu, and a chip shows the active role. The prompt enters the system prompt through one section after the deployment persona; the skills come from a skill provider on each agent's own scope, so only sessions using the role see them. Roles and selections live in the `roles` storage domain, edited on the bundle's Plugins page or through the `roles` tool. Ships four built-in roles (code reviewer, architect, debugger, technical writer). Not yet exercised in a running DSH.
- Removed `dsh-switchboard` and its documentation page.
- `dsh-orbit-bridge` 0.1.0: read-only watch over Orbit projects (P1 execution bridge). Routines and runs persist in the `orbit_bridge` storage domain; every check reads `get_me` and all pages of task statuses and tasks through `ctx.tools.execute()`, and any malformed page, cursor, grant, or task makes it partial. Changes are listed against the last processed run; observed and processed baselines are derived from stored runs. **Check now** records a program-generated change list; `orbit_bridge_observe` and `orbit_bridge_submit_outcome` refuse sessions that can see other tools and guard the open run. A Schedule request is shown as an unreviewed draft and never created. Not yet exercised in a running DSH.
- `dsh-message-edit` 0.1.0: **Edit** above your own messages. **Clear later messages** branches the session from just before the message and sends the edited text there; **Keep later messages** rewrites it in the model context through a `surfaceOp: { op: 'replace' }` record inside `agent.runMaintenance()`, so later messages stay and nothing reruns. Attachments keep their place, and the original bubble carries an **Edited in context** badge.
- `dsh-session-groups`: groups now show as folders at the top of the sidebar session list, with the Workspace list below holding only ungrouped sessions. Folders open and close (saved per browser), rename, delete, reorder by drag, and accept sessions dragged in; dragging a session back onto the Workspace list removes it from its group. Folder rows open the built-in session menu on right-click. The groups page stays available.
- `dsh-pi-tools`: runs on stock DSH 0.2.2-rc.2 and later without DSH source changes. The tool selection is stored as an ignorable `plugin:dsh-pi-tools/selection` Session record and edited through the `conversation.hero.options` slot and an owner-only `/pi-tools/options` route. Result cards use keyed `tool.call.toolview` entries for `codemode` and `tool_search`; Pi `read`, `write` and `edit` now use DSH's built-in rows. Codemode grammar sampling is restored by wrapping pi-ai's `streamSimple`, for models whose compat enables OpenAI grammar tools.
- `dsh-service-tier`: works again on DSH 0.2.2-rc.2 and later, which removed the `llm-pi-ai/model-defaults` waterfall. The plugin now wraps pi-ai's `streamSimple` and sets `service_tier` through `onPayload`; a changed DSH layout logs a warning instead of failing silently. The ⚡ toggle also appears on pi-ai catalog routes such as `openai` that set no `api` of their own.
- `dsh-image-gen` 0.1.0: adds `openai_image` and `grok_image`, which call hosted `image_generation` on an existing Responses provider and save the images to files. The supplied `pi` preset passes both tools through.
- `dsh-pi-mcp` 0.1.0: a Host-only plugin that registers each server in Pi's `~/.pi/agent/mcp.json` with the DSH MCP manager, converts `${VAR}` to `${credential:VAR}`, and follows file edits without a restart. Skips OAuth, `!command`, and SSE entries with a log warning.
- `dsh-pi-tools`: `mcpServers` accepts `'*'` to bridge every global MCP namespace, including ones registered later. The supplied `pi` preset now uses it.
- `dsh-pi-tools`: the conversation tool picker groups Pi, DSH and MCP tools into collapsible sections with selection counts, section checkboxes (whole section, or only the visible matches while filtering), a selected-only view, and expand/collapse all. Filtering always shows matches regardless of fold state. Save, Cancel, Restore defaults and session locking are unchanged.
- Documentation site: reorganized into install, configuration and data, versions and boundaries, and grouped plugin pages, with a page for `dsh-pi-tools`. Plugin versions and DSH ranges are read from package manifests at build time. Replaced references to a nonexistent `patchReload: live` setting with Plugin Manager's `applied` / `restart-required` results.
- `dsh-keep-awake` 0.1.0: a macOS Host-only plugin that prevents automatic idle sleep using the built-in `caffeinate` utility. Keeps display sleep and screen locking unchanged; releases its assertion on plugin disposal or Host exit, including crashes. Includes English and Chinese metadata, an original icon, and usage documentation.
- `dsh-subagent-model` 1.0.0: a read-only model and reasoning-effort label in subagent composers, sourced from the child session's recorded selection. Keeps the main agent's model picker unchanged; includes English and Chinese labels and plugin metadata.
- `dsh-compaction-status` 0.1.0: a compact, single-line compaction indicator above the composer, aligned with the native task dock. Shows elapsed time for automatic compaction and `/compact` without changing compaction behavior.
- `dsh-git-changes` 0.1.0: a composer entry showing the branch and uncommitted changes, including untracked files, with a shortcut to the forge panel. Requires the Change requests & worktrees bundle.
- `dsh-ai-mascot` 0.1.0: draggable GPT / Claude companions that follow the displayed conversation's activity, with compact mode, size and motion preferences, and artwork attribution.
- `dsh-session-groups` 1.0.0: custom session groups in a sidebar panel, with pinned sessions leading each group and a searchable add-session picker. Drag sessions from the sidebar or groups into a group, or onto the new-group drop zone.
- `dsh-auto-review-model` 1.0.0: pick the model, reasoning effort and review prompt that Auto review uses to judge tool calls. A composer chip shows the review model in Auto mode and opens a per-session review log that jumps to each reviewed tool call.
- `dsh-quote-jump` 1.0.0: quotes in user messages become blocks that scroll to the quoted text and highlight it.
- `dsh-tool-lens` 0.1.0: richer tool-call rows; the skill row opens the skill's `SKILL.md` in the right sidebar.
- `dsh-web-access`: custom search uses native expandable tool rows and nullable optional filters. When configured web search is available, it hides built-in `web_search`; X-only search does not replace it, and `web_fetch` stays unchanged.
- Plugin UI styles aligned with host pages and theme tokens (`session-groups`, `auto-review-model`, `model-reference`, `service-tier`).

## 2026-11-10: first public release

- `dsh-model-reference` 1.3.0: type `#` in the composer to insert a model chip with that model's last reasoning effort and fast mode.
- `dsh-service-tier` 1.2.0: a ⚡ toggle beside the model picker that sends `service_tier: "priority"` for OpenAI Responses models.
- `dsh-remember-model` 1.2.0: new sessions start on the model and reasoning effort you picked last.
- `dsh-recent-sessions` 1.0.0: sessions in the `@` menu are listed by last activity, newest first.
- Tests, manifest validation, lint and CI.
